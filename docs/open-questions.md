> 各ドキュメントの本文には `→ OQ-nn` の参照だけを置き、**内容と決め方はここに集約する。**

## 運用ルール

1. **ID は永続**。決着しても番号を再利用せず、欠番にする。
2. 決着したら、この表の行を削除し、**決定内容と理由を [decisions.md](./decisions.md) へ移す**。
   本文側の `→ OQ-nn` も同時に外す。
3. 新規追加は末尾に採番する。**途中に挿入して繰り下げない。**
4. 「決め方」が書けない項目は、**まだ課題として成立していない**。
   何を測れば決まるのかを先に書く。

## 依存関係（★項目のみ）

決着順を誤ると手戻りが出るものを図にする。

```
OQ-02 ゴミの種類・寸法
   ├─→ OQ-05 NFR-7 の目標値（開口とゴミ寸法で決まる）
   └─→ OQ-10 緩衝ライナー

OQ-01 投擲レイアウト ──→ OQ-05 NFR-7 の目標値
   ↑
   └── 柱1 シミュレータの出力（キャッチ可能領域）で机上設計できる

OQ-03 World frame / キャリブレーション ──→ M3 へ進む前提（必須）

OQ-18 ウォッチドッグのタイムアウト（M2a 実測）──→ OQ-19 FR-10 のタイムアウト

OQ-27 Pi 4 継続判断 ──→ OQ-23/25/26 の前提が変わる

OQ-29 通信方式 ──→ OQ-30 メッセージ形式
```

> **最も早く着手すべきは OQ-01 と OQ-02。** どちらも柱1 シミュレータの入力そのものであり、
> かつ他の項目の前提になっている。**実機を待たずに仮値を置ける**点でも先行できる。
