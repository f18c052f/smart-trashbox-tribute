## A. 検出センサー

**採用: RealSense D435**（構成部品一覧 #1）。
深度モジュール・グローバルシャッター・画角・fps は D435i と同一で、
[FR-1](./requirements.md#2-機能要件fr)（3サンプル取得）は問題なく満たす。
グローバルシャッターのため高速移動物体に強い。**カメラは固定運用。**

IMU の用途は「カメラを移動体に載せる案」でのエゴモーション補正のみ
→ 本プロジェクトはカメラ固定方針のため不要と判断した。
再設置時の姿勢把握は**深度データからの床平面フィッティング**で対応する。

> 将来「ゴミ箱搭載案（対応範囲拡大）」に挑戦する場合はエゴモーション補正で IMU が要るため、
> その時点で D435i への置き換えを再検討する。

> 他候補（D435i / Kinect v2 / Luxonis OAK 系）との比較と不採用理由は
> [decisions.md §3](./decisions.md#3-採用しなかった案-部品bom) を参照。

## B. 駆動系

**方式: 3輪オムニ・120°配置（確定）**。既製の全方向ベースは採用せず、**部品から自作**する。
既製ベースは 0.6 m/s 級かつ結局モータ換装が必要になるため、最初から自作する方が安く確実と判断した。

詳細な仕様・計算・注意事項は **[drivetrain-spec.md](./drivetrain-spec.md) を正**とする。
該当する部品は構成部品一覧 #3〜#9。

### ホイールの確定寸法（2026-08-30、メーカー図面より）

| 項目 | 値 | 用途 |
|---|---|---|
| 外径 / 幅 | **Ø60 / 25.6mm** | 車軸中心高さ 30mm（→ [§6.3 最低地上高](./drivetrain-spec.md#63-最低地上高)） |
| **中心穴** | **Ø12.5mm** | ⚠️ **6mm シャフトに直結できない**（下記） |
| ボルト円 | **Ø21** と **Ø28** | 取付インタフェース。CAD の起点 |
| 取付穴 | **5-Ø3.2** / **6-Ø3** | ⚠️ どちらの穴群がどちらのボルト円かは**要確認** |
| ローラー | 幅13mm・長さ18.5×5個/枚・**2枚計10個**・ナイロン／PE | グリップと転がり抵抗（→ §11 #8） |
| **重量** | **80g/個 ＝ 3輪で240g**（アルミ合金） | 重心計算。**車軸高さ 30mm にあるため重心を下げる側に効く** |
| 耐荷重 | 3kg/輪（3輪で9kg） | 2kg 級機体に対して十分 |
| その他 | 内側 Ø48、側面オフセット 5.5 / 2.5 | — |

**接続経路**（2026-09-03 に現物で確認済み）:

```
JGB37-520（6mm Dシャフト）
   ↓ 直結・追加加工不要
6mm ハブ（Nexus 18020 相当品）
   ↓ ボスが Ø12.5 の中心穴へ入り、ボルト円でネジ止め
60mm ダブルオムニホイール（Nexus 14145 相当品）
```

**ホイール中心穴 Ø12.5 はハブのボスを受ける穴**であり、シャフト径 6mm と比較する対象ではない。

### ハブ Nexus 18020 の確定寸法（2026-09-03、メーカー資料より）

| 項目 | 値 | 用途 |
|---|---|---|
| 内径 | **Ø6**（+0.02/−0） | ⚠️ **真円。D 穴でもキー溝でもない**（下記） |
| 外径（フランジ） | **Ø28** / 厚さ **4mm** | 軸方向スタックの起点 |
| ボス | **Ø12 × 12mm** | ホイール中心穴 Ø12.5 へ入る |
| 全長 / 穴の長さ | **16mm** | ⚠️ シャフト長 15.5mm に対しほぼ全長で噛む＝**軸方向の調整代が無い** |
| ボルト円 | **Ø21**、**3-Ø3.2** | ホイール側の **6-Ø3 が Ø21 側**であることが導ける（120°で3本使う） |
| 止めネジ | **M4** ×1 | ⚠️ **トルクを受けるのはこれ1本だけ**（下記） |
| 材質 / 重量 | アルミ合金 / **12g**（3個で36g） | 重心への寄与は無視できる |

> ⚠️⚠️ **トルク伝達は M4 イモネジ1本が担う。**
> ハブ穴は**真円**で D カットもキー溝も無い。一方モータシャフトは 6mm **D** である。
> したがって **イモネジがシャフトの D カット平面に当たっていれば保持でき、
> 丸い面に当たっていれば滑る。**
> ⚠️ **滑ってもエンコーダはモータ軸側で回り続けるため、制御側からは検出できない。**
> ストールトルクは 3.1 kg·cm ＝ 約 0.30 N·m と小さいため、D 面に正しく当たっていれば
> M4 で保持できる見込みだが、**組付け時に平面へ当てることを手順として明示する。**

**軸方向スタック**（フランジ厚 4mm ＋ ホイール半幅 12.8mm から導出。⚠️ 実測で確認する）:

```
ギヤボックス端面 ─4mm→ ホイール内側面 ─12.8mm→ ホイール中心面 ─12.8mm→ ホイール外側面
                          （端面から 16.8mm）            （端面から 29.6mm）
```

この値が **OQ-07（フレーム外形＝ホイール間隔）** の計算に直接入る。

### 付属ブラケットと駆動ユニットの実測（2026-09-03）

L 字（コの字）。**外形 41.3 × 38.8mm、モータ軸方向に長い**。取付面に穴が2つ見える。

| 項目 | 実測値 | 備考 |
|---|---|---|
| モータ全長 | **70.6mm** | エンコーダ込みかは要確認 |
| **取付面 → 接地点（垂直）** | **60.0mm** | ⚠️ **ベース板の高さを決める値** |
| 取付面 → ホイール中心（軸方向） | **33.9mm** | ⚠️ **方向が軸方向であることの確認待ち**（下記） |

> **整合の確認**: 仮に 33.9 と 60.0 の両方が垂直だとすると差は 26.1mm となり、
> ホイール半径 30mm（Ø60、図面確定）と **3.9mm 合わない。**
> したがって**2つは別方向の測定**であり、60.0 が垂直・33.9 が軸方向と読むと矛盾しない
> （垂直方向では 60.0 − 30 ＝ 30.0mm が取付面から車軸までの高さになり整合する）。

**⚠️ 最低地上高との衝突は解消した**（当初の懸念を訂正）。

```
    ┌──────────── 取付面（ベース板の下面）＝ 床から 60mm
    │  ↕ 約48.5mm の空間
┌───┴───┐
│ モータ │ ← 下面は床から 11.5mm（[§6.3](./drivetrain-spec.md#63-最低地上高)）
└───────┘
════════════ 床
```

ブラケットを反転させ**モータをベース板から吊り下げる**構成が成立する。
ベース板を床から 60mm に置けるため、[§6.3](./drivetrain-spec.md#63-最低地上高) の
「ベース板がモータより下に来て入らない」という当初の懸念は該当しない。

**OQ-07（フレーム外形＝ホイール間隔）が式になる**（33.9 が軸方向であることが前提）:

```
R（機体中心 → ホイール接地点）＝（機体中心 → 取付面の距離）＋ 33.9mm
```

駆動ベースの半径を決めれば R が定まるため、**設計変数が1つに減る。**

> ⚠️ 別途 105.6mm という測定値があったが、**基準面が不明のため破棄した**（2026-09-03）。

> **未確認（CAD 確定に必要。→ [drivetrain-spec.md §11](./drivetrain-spec.md#11-確定事項--実機確認事項--将来オプション)）**:
>
> - ⚠️ **イモネジがシャフトの D カット平面に当たっているか**（丸い面だと滑る。上記）
> - **ブラケットの取付穴の数・ピッチ・位置**、および**取付面の向き**（上記のレイアウト判断に直結）
> - **荷重下の実効転がり半径**。公称 Ø60 は図面で確定したが、
>   **ローラーが潰れる分**は実測でしか出ない。オドメトリ（[FR-6](./requirements.md#2-機能要件fr)）と
>   `trajectory_sim` の `wheel_diameter_mm` の両方へ効く。
>   ⚠️ **「予測は合っているのに届かない」という最も切り分けにくい形で現れる**
> - 導出した軸方向スタック（端面から 16.8 / 29.6mm）の**実測による確認**

**将来モータを変更する場合も 6mm Dシャフト互換を維持する**（CON-4）。

**理論周速（参考値。実車速度を保証しない）**:
530 RPM × 60mmホイール = 530/60 × π × 0.060 ≈ **1.66 m/s（無負荷）**。定格 407 RPM では ≈ 1.28 m/s。
**実車速度は M2b で実測する。**

## D. 電源・保護・ノイズ対策

該当する部品は構成部品一覧 #10〜#21。以下は**使い方と数値の根拠**。

- **0.1µF セラミック**: 各モータ端子の直近に1個ずつ（モータノイズ対策）／LiPo 分圧の ADC 入力点 → GND
- **1000µF/35V**: モータドライバ付近。必要に応じて2個を分散配置
- **100kΩ + 27kΩ**: LiPo 電圧監視の分圧（分圧比 ≈ 0.2126、12.6V → 約 2.68V）
- **G3 CHARGER**: 1500mAh に対して 1.5A 設定で約 1C。**JST-XH バランス端子**を使用。
  ⚠️ バッテリー側バランスコネクタ形状は**現物確認結果を優先**する。
- ⚠️ **1500mAh は容量であって最大出力電流ではない。** 35C からの理論値 1.5Ah × 35 = 52.5A を
  **実使用上の保証最大電流として扱わない。**
- ⚠️ **10A の根拠**: ストール 2.3A × 3 = 約 6.9A ＋ 制御回路分。
  **5A では通常の急加速でも不要動作の可能性がある。**
  10A は短絡・配線事故・電源バス重大故障からの保護用であり、
  **モータの通常運転電流を制限するものではない。**
  モータ個別のロック保護は**エンコーダ＋ソフトウェア**で行う
  （[drivetrain-spec.md §5](./drivetrain-spec.md#5-モータロック保護ソフトウェア)）。

> ただし**跳ね返りが実際に問題になるかは未検証**のため、
> **先回りして購入せず、M3 で実際に投げてから要否を判断する。**

> **整備スタンドについて**: [M2a-0](./requirements.md#8-段階的開発マイルストーン) では、
> **ホイールを浮かせた状態**でモータの回転方向・エンコーダの符号・`ENCODER_COUNTS_PER_WHEEL_REV` を確認する。
> 接地したまま初通電すると、極性が逆のまま機体が予期せず走り出す。
> 造形物なので**追加購入は不要**だが、**M2a より前に用意しておく必要がある**
> （[drivetrain-spec.md §6.2](./drivetrain-spec.md#62-3dプリント範囲)）。
> 最低地上高が小さい構成（[§6.3](./drivetrain-spec.md#63-最低地上高)）のため、
> **フレーム下面ではなくホイール外側または駆動ベース端部で支持する形状**にすること。

> ゴミ箱本体まで全面3Dプリントする構成は**標準案から外した**（重量・造形時間・剛性のいずれも不利）。
> 金属切削加工は要求しない（CON-1）。

## H. 開発・検証用機材

**完成品の構成部品ではないが、開発・検証に必要な機材。**
方針は [original-features.md](./original-features.md)（独自機能＝道具）を正とする。

| 用途 | 機材 | 扱い |
|---|---|---|
| **手動テレオペ**（[FR-13](./requirements.md#2-機能要件fr) / [M2a](./requirements.md#8-段階的開発マイルストーン)） | SONY **DualSense**（PS5 コントローラ） | **手持ち。購入対象ではない** |
| M2a-0 の台上試験 | **整備スタンド**（3Dプリント） | 自作（→ [§E](#e-機構3dプリンタ活用)） |
| **電気系ブリングアップ E-1〜E-3**（→ [drivetrain-spec.md §10.2](./drivetrain-spec.md#102-m2a-0-の前に必ず行う電気系ブリングアップmust)） | **安定化電源**（**電流制限機能つき**。12V / 3A 以上） | ⚠️ **手持ち確認要** |
| 電気系ブリングアップ E-3 | **可変抵抗**（10kΩ B カーブ程度） | ⚠️ **手持ち確認要**。ESP32 の ADC1 へ入れて PWM デューティへ写す |
| 電圧・導通確認全般、ADC 校正（[§9.3](./drivetrain-spec.md#93-満充電-126v-対策)） | **テスター（マルチメータ）** | ⚠️ **手持ち確認要** |

> ⚠️ **安定化電源は「あると便利な機材」ではなく MUST である。**
> 3S LiPo は短絡時に配線を溶かす電流を流せる一方、**電流制限をかけた安定化電源は止まる。**
> 初通電を LiPo で行わないこと自体が保護策であり、
> [drivetrain-spec.md §10.2](./drivetrain-spec.md#102-m2a-0-の前に必ず行う電気系ブリングアップmust) の E-1 がこれを規定する。

### DualSense を採用した理由

- **手持ちであり追加費用が発生しない。**
- アナログスティック2本が **(vx, vy) と ω** にそのまま対応するため、
  3輪オムニの逆運動学の入力形と一致する
  （[drivetrain-spec.md §10.1.3](./drivetrain-spec.md#1013-入力マッピングと運転上の制約)）。
- トリガー／ボタンを**デッドマン**に割り当てられる。
- ハプティクスがあるため、モータロック検出等を**振動で通知**できる（任意）。

> ⚠️ **接続方式（BT 直結か PC 経由か）は未確定**（→ [OQ-16](./open-questions.md#d-移動体制御テレオペ)）。
> 第一候補は移動体 ESP32 への Bluetooth Classic 直結だが**実機未検証**であり、
> 動作しない場合は PC 経由（Serial / UDP）へ落とす。**いずれの案でも追加部品は発生しない見込み。**

> ⚠️ **テレオペは安全装置ではない。**
> 物理的な非常停止手段は別途必要（→ [OQ-13](./open-questions.md#c-電源安全)）。

   → [development-environment.md §16](./development-environment.md#16-実機セットアップ手順)。

6. **整備スタンドを造形しておく**（→ [§E](#e-機構3dプリンタ活用)）。
   M2a-0 はホイールを浮かせた状態で行うため、**接地走行より先に必要**になる。
