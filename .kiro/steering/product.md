# Product Overview

投げられたゴミの**落下地点を空中で予測**し、床を走行するゴミ箱が**落下時刻までにそこへ移動して受け止める**システム。
倉田捻氏の「Smart Trashbox」（文化庁メディア芸術祭受賞）の tribute 実装であり、個人の趣味プロジェクト。

**現在のフェーズ: 設計・要件策定。ソフトウェアは一行も存在しない。**
リポジトリにあるのは `docs/` の設計ドキュメントのみ。

## Core Capabilities

| # | 能力 | 担当 |
|---|---|---|
| 1 | 飛来するゴミの3D位置を時系列で取得 | 固定側（RealSense D435 + Raspberry Pi 4） |
| 2 | 放物運動モデルから床面到達座標と到達時刻を推定 | 固定側 |
| 3 | 目標座標を移動体へ低遅延で無線送信 | 両側 |
| 4 | 全方向走行で目標座標へ移動し、自己位置を把握 | 移動体（ESP32 + 3輪オムニ） |
| 5 | 異常時に自律停止（ロック・低電圧・通信途絶・領域外） | 移動体 |

**「知能（固定側）」と「身体（移動体）」を分離し、両者を目標座標データだけで繋ぐ。**
この骨格は元システム由来であり、**変更しない**。画像・Depth フレームは移動体へ送らない。

## The Core Difficulty: 時間予算

このプロジェクトの成否は**ほぼ一点**に集約される。

```
総飛行時間 0.6〜1.2s − システム側オーバーヘッド 0.2〜0.3s = 移動体の持ち時間 0.3〜1.0s
```

この持ち時間で横方向の狙い誤差（想定 0.3〜0.8m）を詰められるか。
したがって性能は **最高速度ではなく短時間移動性能**（0.4 / 0.6 / 0.9 秒で何 m 動けるか）で評価する。

> ⚠️ 時間予算表の数値は**すべて設計上の想定値**であり、実測値ではない。
> 特に「リリース〜検出開始」は完全に未検証。M1 で最優先に実測する。

## Success Criteria

**唯一の最終合否条件は NFR-7（キャッチ成功率）。**

- 定義した投擲レイアウトで N 回投擲したときにキャッチが成立した割合
- 成立＝**開口内に入り、かつ跳ね出さずに留まる**こと（「入れた」と「キャッチできた」は別問題）
- 目標値・N ともに未設定。**M1・M2 の実測後に、達成可能なレンジを見てから決める**

> ⚠️ NFR-1〜NFR-6 はすべて**部分指標**である。全部満たしてもキャッチできるとは限らず、
> 一部を満たさなくてもキャッチできれば成功。**部分指標の達成を完了と呼ばない。**

## Milestones

| 段階 | 内容 | 主眼 |
|---|---|---|
| **M1** | 予測の可視化（移動体なし） | 予測精度と**時間予算表の実測検証** |
| **M2a** | 手動テレオペによる足回りブリングアップ | 配線・符号の**定性確認**（合否判定に使わない） |
| **M2b** | 短時間応答の自動計測 | **NFR-1 の検証** |
| **M3** | 予測→通信→走行の結合、静的な短距離キャッチ | 系として繋がるか |
| **M4** | 高速化・チューニング、復帰動作 | **NFR-7 を実測し完了判定** |

M2a → M2b の分割は、定量計測が「逆運動学・配線・エンコーダ符号が正しい」ことを
暗黙の前提にしていたため。組み立て直後に起きるのは性能不足ではなく**配線・符号のバグ**であり、
自動計測スクリプトでのデバッグは最も切り分けが難しい。**先に手動で潰す。**

## Scope Boundaries

### 対象とする

- **屋内・平坦な床**（フローリング等）
- 人が 2〜3m 先から山なりに投げる
- 初期 MVP では**投擲位置・方向を固定し、必要横移動量を小さくする**ことを許容する
  （これは逃げではなく**システム設計の一部**）

### 対象としない

- 段差越え、厚いカーペット走行
- 金属切削加工を要する設計（3Dプリンタのみ。ボール盤・旋盤・フライスなし）
- ゴミの種類判別（分別）— 別プロジェクト級
- 移動体へのカメラ搭載（固定側/移動体の責務分離を壊す）

## 独自機能の位置付け

M1〜M4 は元動画の忠実再現であり、機能的なオリジナリティはない。
独自の取り組みは **「演出ではなく道具」**とする ＝ *M1〜M4 を実行するために必要だが元動画には存在しないもの*。

| 柱 | 内容 | 判断 |
|---|---|---|
| 柱1 | 軌道シミュレータ | **採用**（最優先。ハード完成前に成立性を評価できる唯一の手段） |
| 柱2a | 構造化ロギング | **採用**（独自機能というより前提条件） |
| 柱2b | ライブダッシュボード | 保留（M3 で再判断） |
| 柱3 | 投擲アーカイブ／ベンチマーク | 見送り（M1 でデータが貯まってから再判断） |
| 柱4 | 手動テレオペ | **採用**（M2a のブリングアップ手段） |

**LED・音・キャラクター性といった演出は、難所（時間予算）を1ミリも助けない。**
足すのはいつでもできるので、後回しにする。
