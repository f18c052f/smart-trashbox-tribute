# Part 1 — 図に描く内容

## 1. 全体ブロック

→ **図1（電源系統）を参照**:
https://claude.ai/code/artifact/e98e597f-e794-46dd-a881-f42f51099272

12V は1系統のみである。バッテリの＋が F1（10A ヒューズ）を通って `VM` という
1本のバスになり、そこから U1〜U3（AE-TB67H450）と U4（BP5293-50）へ分かれる。
U4 の 5V が **JP1 を経て** ESP32 DevKit の `VIN` へ入る（→ §2.2.1）。

**U4（BP5293-50）の定格**（2026-09-21 に確認、`docs/bom.md` には未記載）:
入力 7〜26V ／ 出力 5V ±3% ／ 出力電流 max 1A ／ スイッチング 570kHz ／ リップル 50mV ／ SIP3。
- 3S LiPo の 9.0〜12.6V は入力範囲の内側 ✅
- 必要なピークは ESP32 の BT Classic 送信 約130mA ＋ ボード 20mA ＋ エンコーダ3個 45mA
  ≒ **約300mA** であり、1A に対して3倍以上の余裕がある ✅
- 🔶 副作用: DevKit の 3.3V LDO が (5−3.3)×0.3 ≒ 0.5W を捨てる。DevKit が温かくなるが
  ESP32 DevKit 共通の性質であり故障ではない。

`SW1` / `TB1` の2ブロックは **本 Spec が決めない**（要件 3.9、`wiring.md` §4）。
図には「ここに入る」という**破線の受け口**として描き、実線で結線しないこと。
これらを実線で描くことは、要件 3.9 が防ごうとしている誤り（機構側の決定の先取り）
そのものである。

## 2. ネット一覧

図の骨格。⚠️ **GPIO 列は `kShippedPinPlan` の転記であり、図の側で変えてはならない。**

### 2.1 12V 動力系

| ネット | 接続点 | 線種 |
|---|---|---|
| `BAT+` | LiPo XT60(+) → F1 入力 | 14AWG |
| `VM` | F1 出力 → (SW1) → (TB1) → U1/U2/U3 の VM、U4 の Vin、C1/C2 の (+)、R1 の上端 | 14AWG |
| `PGND` | LiPo XT60(−) → **星形接地点 `GND-STAR`** | 14AWG |
| `OUT0+/−` | U1 OUT1/OUT2 → M0 赤/白 | 動力線 |
| `OUT1+/−` | U2 OUT1/OUT2 → M1 赤/白 | 動力線 |
| `OUT2+/−` | U3 OUT1/OUT2 → M2 赤/白 | 動力線 |

⚠️ 赤と白を入れ替えると回転方向が反転する（`wiring.md` §1.2）。
対応の確定はタスク 8.4（ドライバを介さないモータ単体確認）が行う。
**図の段階では「OUT1→赤 / OUT2→白」を仮の基準として描き、その旨を注記する。**

### 2.2 低電圧系

| ネット | 接続点 |
|---|---|
| `+5V` | U4(BP5293-50) Vout → **JP1（5V 切り離しジャンパ）** → ESP32 DevKit `VIN`(5V) |
| `+3V3` | ESP32 DevKit `3V3` → エンコーダ VCC（青）×3、可変抵抗 VR1 上端 |
| `SGND` | ESP32 `GND` → エンコーダ GND（黒）×3、VR1 下端、C6(−側) |

⚠️ **エンコーダは 3.3V 駆動**（`docs/drivetrain-spec.md` §7）。
`+5V` をエンコーダへ配らないこと。5V 出力信号を ESP32 GPIO へ直接入れない。

#### 2.2.1 JP1（5V 切り離しジャンパ）⚠️ 新規

| 場面 | JP1 | `+5V` の供給元 |
|---|---|---|
| 書き込み・ログ確認（USB あり。タスク 8.5 / 7.1 BenchApp） | **外す** | USB のみ |
| 実走行（USB なし） | **挿す** | BP5293-50 のみ |

- **目的**: USB の 5V と BP5293-50 の 5V が同じ線に並列でぶら下がるのを防ぐ。
  電圧の高いほうが低いほうへ流し込み、**PC の USB ポートへ逆流する**か
  **BP5293-50 の出力へ逆流する**。降圧コンバータは出力側からの電流を想定していない。
- ⚠️ **切るのは `+5V` の1本だけ。`SGND` は常に繋いだままにする。**
  切るとドライバの論理基準と ESP32 の基準が別物になる。
- **なぜ調べずにジャンパにしたか**: DevKit の 5V ピンが USB VBUS と直結かダイオード経由かは
  基板の版によって違い、版が変わるたびに調べ直しになる。JP1 があればどちらでも成立する。
- モータの 12V は別系統なので、JP1 を外しても USB 給電のままモータは回せる。

### 2.3.1 ドライバの残り4端子（ESP32 に紐づかない）

⚠️ **タスク 2.1 の結線表は ESP32 の端子しか扱わないため、ここが抜けていた。**
TB67H450FNG は8端子あり、上記の `IN1`/`IN2` と `OUT1`/`OUT2`/`VM`/`GND` のほかに
`VREF`（電流設定）と `RS`（電流検出）がある。**未接続では成立しない。**

| 端子 | # | 接続先 | 出典 |
|---|---|---|---|
| `VREF` | 4 | ESP32 `3V3`（3.3V）＋ 0.1uF → `SGND` | アプリケーションノート 4.1 / 7.3 |
| `RS` | 7 | **0.22Ω（1W 以上）→ `PGND`**。IC の直近 | 同 7.4 表7-2（1.5〜3.0A 用） |
| `VM` | 5 | `VM` バス ＋ **0.1uF セラミック → `PGND`**。IC の直近 | 同 7.3 表7-1 |
| `GND` | 1 | `PGND` → `GND-STAR` | 同 7.1 |

- ✅ **センス抵抗は未実装であることを実測で確認済み**（2026-09-21、→ §7.2）。
  0.22Ω の外付けが必要である。

| ネット | 接続点 |
|---|---|

## 3. 接地の分離と合流点（要件 3.5）

⚠️ **これは表では表せない事項であり、要件 3.5 が図に求めている中心である。**

### 3.1 2系統に分ける

| 系統 | 流れる電流 | 含むもの |
|---|---|---|
| **動力接地 `PGND`** | 最大 約6.9A（2.3A × 3、ストール時） | LiPo(−)、U1〜U3 の GND、C1/C2 の(−)、U4 の入力 GND |
| **信号接地 `SGND`** | 数百 mA（ESP32 + エンコーダ） | ESP32 GND、エンコーダ GND(黒)×3、C6、VR1 |

### 3.2 合流は1点だけ（`GND-STAR`）

```
        LiPo XT60(−)
             |
        +----+---- GND-STAR ----+   <- 図に名前付きで1箇所だけ置く
        |        （C1 の (−) 端子を星の中心に兼ねる）
        |                       |
   [ 動力接地 ]            [ 信号接地 ]
   U1/U2/U3 GND            U4 出力GND -> ESP32 GND
   C2 (−)                  -> エンコーダ GND x3 / C6 / VR1
   U4 入力GND
```

- **`GND-STAR` は C1（1000uF）の(−)端子とする。** バルクコンデンサの直近が、
  モータ電流のリターンが最も落ち着く点である。
- **判断のしかたは1つ**: ⚠️ **エンコーダの黒から ESP32 の `GND` ピンまで指でたどり、
  その経路にモータ電流が流れる区間があるかを見る。** あれば誤り。
  エンコーダは A相/B相 を「自分の黒を 0V として」出し、ESP32 は「自分の GND を 0V として」
  読む。この経路にエンコーダ自身の消費電流（十数 mA）しか流れていなければ 0V はずれない。
- ⚠️ **効くのは DC の電位差よりスパイクである。** 配線と端子で 20mΩ、6.9A でも 138mV 程度で
  ロジックしきい値には余裕がある。危ないのは PWM の切り替わり瞬間で、配線の
  インダクタンス（20cm で約 200nH）に L·di/dt が立つ（1A/us なら 0.2V）。
  **PCNT はエッジを数えるため、スパイク1発がパルス1個の誤カウントになる。**
  壊れるのではなく静かに数え間違える故障である。
- ⚠️ **「エンコーダの黒と白がつながる」ではない。** 接地でつながるのは
  `エンコーダ黒 ─ ESP32 GND ─ ドライバ GND(pin1) ─ C1/C2 の(−) ─ LiPo(−)` である。
  **白（`OUT2`）はこの仲間ではない**（→ §5.1.1）。
- ⚠️ **信号接地を、動力電流が流れる配線の途中へぶら下げない（デイジーチェーン禁止）。**
  ストール 6.9A が動力接地の線材抵抗に落とす電圧が、そのまま ESP32 の
  基準電位の揺れになる。合流を1点に絞る目的はこれを断つことである。
- ⚠️ **合流点が2箇所以上あると接地ループになる。** 図の上で `GND-STAR` から
  出る線が何本で、どれが動力側・どれが信号側かを**一目で数えられるように描く**
  こと。この「数えられるか」がタスク 2.3 の目視照合（§8 S-3）の対象である。
- ⚠️ **AE-TB67H450 の GND は動力と論理で共通**（IC の GND ピンが1本）。
  したがって `IN1`/`IN2` の論理基準は動力接地側の電位である。ESP32 の
  `SGND` との間には動力接地の IR 降下ぶんの差が乗る（仮に 20mΩ の線で
  2.3A なら 46mV）。この差が論理しきい値に対して十分小さいことが
  星形接地を採る前提であり、**図にはこの意図を注記する**。
  → 実測はタスク 8.3（E-1）で行う。測定点は §5.2 TP7。

## 4. ノイズ対策部品と実装位置（要件 3.6）

⚠️ **接続先だけでなく「どこに置くか」を図へ書く。** 要件 3.6 が接続先だけでは
足りないと述べているのは、これらの部品は置き場所を外すと接続が正しくても

### 4.1 0.1uF / 50V X7R（C3, C4, C5）— モータ端子

| 部品 | 接続 | **実装位置の制約** |
|---|---|---|
| C3 | M0 の赤−白 間 | ⚠️ **モータ本体の端子に直付け。** ドライバ側の OUT1/OUT2 端子台ではない |
| C4 | M1 の赤−白 間 | 同上 |
| C5 | M2 の赤−白 間 | 同上 |

- 抑えたいのはブラシが発生させるノイズであり、**発生源で閉じ込める**ことに
  意味がある。ドライバ側に置くと動力線全長がアンテナとして残る。
- ✅ **前者（モータ1個につき端子間に1個・計3個）で確定した。** `docs/bom.md` §D の
  「各モータ端子の直近に1個ずつ」は読み方が2通りあるが、数量欄が「一式」で
  縛りが無く、後者（端子1本につき1個を筐体へ落とす・計6個）を採ると
  **筐体アースの扱いを別に決める必要が生じる**ため、この段では過剰である。
  ⚠️ 意図が後者だったと判明したら本表を3行→6行へ増やすこと（→ §7.2 #5）。

### 4.2 1000uF / 35V 電解（C1, C2）— ドライバ付近

| 部品 | 接続 | **実装位置の制約** |
|---|---|---|
| C1 | `VM` − `GND-STAR` | ⚠️ 分岐の**入口**側。かつ `GND-STAR` の中心を兼ねる（§3.2） |
| C2 | `VM` − `PGND` | ⚠️ 分岐の**末端**側ドライバ（U3）の VM/GND 端子の直近 |

- `docs/drivetrain-spec.md` §8.5 は「モータドライバ付近。必要に応じて2個を
  分散配置」とのみ述べる。上記の入口／末端という**分散のしかたは本書の提案**で
  あり、出典からの転記ではない。✅ **図はこの提案どおりに描いた**
  （C1 が `GND-STAR` の中心を兼ねる設計と噛み合うため）。
- ⚠️ **VM−GND のループ面積を最小にする。** ドライバの VM と GND を長い線で
  引き回した先にコンデンサを置くと、ループのインダクタンスがスイッチング時の
  電圧スパイクを作る。

### 4.2.1 0.1uF セラミック（C7, C8, C9）— 各ドライバの VM−GND ⚠️ 新規

| 部品 | 接続 | **実装位置の制約** |
|---|---|---|
| C7 | U1 の `VM` − `GND` | ⚠️ **IC のすぐ横**（アプリケーションノート 7.3） |
| C8 | U2 の `VM` − `GND` | 同上 |
| C9 | U3 の `VM` − `GND` | 同上 |

- ⚠️ **これは C1/C2（1000uF 電解）の代わりではない。両方が要る。**
  アプリケーションノート 表7-1 は VM−GND 間に電解とセラミックの両方を挙げており、
  「特にセラミックコンデンサを IC 近傍に配置頂くことで高周波数の電源変動や
  ノイズを抑えることに効果的」と述べている。電解は高い周波数では
  インダクタンスが効いて応答できない。
- 表7-1 の電解の推奨は 47〜100uF であり、本設計の 1000uF は大きく超える。
  これは**バッテリバスのバルクとして意図的**であり、回生電流の受け皿としても有利である。

### 4.2.2 0.1uF セラミック（C10, C11, C12）— 各ドライバの VREF−GND ⚠️ 新規

- アプリケーションノート 表7-1 は「ご使用環境に合わせ、必要に応じて」としている。
- 本設計では `VREF` を ESP32 の `3V3` から引き回すため、`VREF` 端子の直近に置く。

### 4.2.3 電流検出抵抗（RRS1, RRS2, RRS3）— 各ドライバの RS−GND ⚠️ 新規

| 部品 | 値 | **実装位置の制約** |
|---|---|---|
| RRS1〜3 | 0.22Ω / 1W 以上（2W 推奨、酸化金属皮膜） | ⚠️ **IC の直近**。間に配線が入るとその抵抗ぶんだけ設定値がずれる（同 7.4） |

- ⚠️ **巻線型（セメント抵抗に多い）は避ける。** インダクタンスが電流検出にノイズとして乗る
  （IC 側に tBLK 3.6us の不感帯があるため致命的ではないが、選ぶ理由もない）。
- 消費電力は制限値いっぱいで 1.5^2 x 0.22 = 約 0.5W。通常走行ではずっと小さい。
- ⚠️ **これは「付けるか付けないか」の選択ではない。** `RS` は必ず GND へ繋がないと
  電流の戻り道がなく回路が成立しないため、選択肢は**「その場所に 0.22Ω を入れるか、
  ただの線を入れるか」**である。配線も基板設計も変わらない。
- **性能への影響はほぼ無い。** DC モータの機械出力が最大になるのは電流がストールの半分
  （2.3A / 2 = 約 1.15A）のときであり、**1.5A 制限はこれより上**にある。
  削られるのは速度ゼロ付近の踏ん張りトルクのみ。3輪合計も 4.5A となり、
  10A ヒューズと配線への負担が軽くなる（無制限なら 6.9A）。
- ⚠️ **データシートは電流制限を要求していない。** 「定電流制御機能を無効にしたい場合は、
  RS 端子を GND に接続し、VREF 端子に 1~5V を入力してください」（データシート p.10 /
  アプリケーションノート 4.1）とあり、**無効化は正式な構成**である。0.22Ω は
  「定電流制御を使う場合の推奨値」として表7-2 に載っているにすぎない。
  **1.5A に絞るのは本書の判断であり、データシートの要求ではない（安全側に寄せた判断）。**
- 判断の根拠は熱計算である。ストール 2.3A で 2.3^2 x 0.6 = **3.17W**、許容損失 2.85W を超える
  （Ron 最大 0.8Ω なら 4.23W）。制限 1.5A なら 1.35W で余裕がある。
  ⚠️ **ただし前提が2つある**: (a)「連続で」2.3A が流れること（一瞬のストールは熱容量が吸収する）、
  (b) PD 2.85W は JEDEC 4層基板の値であること（2層モジュールではより小さい）。
  さらに ⚠️ **データシート自身は注1 で Iout ≦ 2.45A を目安として許容しており**、
  PD 2.85W とは緊張関係にある。**どちらとも読める。**
- **この制限が効くのはブリングアップの間である。** 2.3A が流れるのは異常時だけで
  本来はソフトのモータロック保護の領分だが、⚠️ **その発火試験（タスク 9.4）は
  開ループ確認（8.5）や M2a-0（9.1）より後**であり、それまで IC を守るものが
  ハードの制限しかない。逃げ道の TSD はデータシートが
  「積極的に活用するような使用方法は避けてください」と明記している。
- **可逆である。** 9.4 でソフト保護を確認したあと加速が足りなければ、
  VREF を 4.0V まで上げて 1.82A にするか、線へ替える。半田を1箇所やり直すだけ。
  逆に最初から線にすると、制限が欲しくなったときに部品調達からやり直しになる。
- **付けない判断も正当である。** その場合の条件:
  (1) `RS` を `PGND` へ直結し `VREF` は 3.3V のまま、
  (2) タスク 8.5 / 9.1 で**モータを長時間ストールさせない**運用（壁に押し付けない・
  手で止めない・ドライバが熱ければ止める）を、タスク 9.4 でソフトのロック保護を
  確認するまで守る。

### 4.3 0.1uF（C6）— ADC 入力点

| 部品 | 接続 | **実装位置の制約** |
|---|---|---|
| C6 | `VBAT_SENSE` − `SGND` | ⚠️ **ESP32 の GPIO32 ピンの直近。** 分圧抵抗側の端ではない |

### 5.1 極性を持つ部品（向きを図に明示）

| 部品 | 極性 | 誤ったときに起きること |
|---|---|---|
| C1 / C2（1000uF 電解） | (+)→`VM`、(−)→`PGND` | ⚠️ **逆挿しで破裂・発火。** 12V を逆極性で受ける |

#### 5.1.1 ⚠️ `OUT1`/`OUT2`（赤・白）は GND ではない

「モータ電源＋／−」という呼び方は**どちら向きに繋ぐと正転するか**を表しているだけで、
電源の極性ではない。H ブリッジでは赤も白も**能動的に駆動される出力**である
（データシート p.6 入出力ファンクション）。

| モード | IN1 | IN2 | `OUT2`（白）の電位 |
|---|---|---|---|
| 正転 | H | L | 0V |
| 逆転 | L | H | ⚠️ **12V** |
| ブレーキ | H | H | 0V |
| ストップ | L | L | Hi-Z（浮く） |

⚠️ **白へエンコーダの黒を繋ぐと、逆転中に 12V が直撃してエンコーダが即死する。**
これは `wiring.md` §1 冒頭の線色の罠が別経路で再発する形であり、**図に注記する**。

⚠️ **電解コンデンサ2個が本機で最も危険な極性部品である。** 図では (+) 側を
明示記号で描き、`VM` へ繋がることを線の行き先だけに頼らず示すこと。

## 7. ⚠️ 作図前に決着が要る事項

### 7.1 ✅【決着済み: 案B】PWM/DIR 2線と TB67H450 の IN1/IN2 が噛み合わない

**これが本たたき台で見つかった唯一の設計上の穴であった。**
**2026-09-21 に案B（ファームを IN1/IN2 直接駆動へ変える）で決着した。**
以下は決着に至った経緯の記録である。

現状のファームウェア（`firmware/src/teleop/motor_ledc.cpp`、タスク 3.2 完了済み）は
輪あたり2本を次のように駆動する。

- `kMotorPwm`: LEDC で 20kHz の PWM、デューティ = |指令| （0〜1023）
- `kMotorDir`: **素の GPIO。前進で H、後進で L の静的レベル**

一方 TB67H450 は `IN1` / `IN2` の2入力で、真理値表は次のとおり（🔶 **データシートで
要確認**。下表は Toshiba H ブリッジの一般的な表）。

| IN1 | IN2 | 動作 |
|---|---|---|
| L | L | ストップ（両出力オフ） |
| H | L | 正転 |
| L | H | 逆転 |
| H | H | ブレーキ（短絡制動） |

⚠️ **`kMotorPwm`→`IN1`、`kMotorDir`→`IN2` と素直に配線すると破綻する。**

| 指令 | IN2 | IN1 | 実際に起きること |
|---|---|---|---|
| 前進・デューティ 0 | H | L | **(L,H) = 全速逆転** |
| 前進・デューティ 100% | H | H | (H,H) = ブレーキ（停止） |
| 後進・デューティ 0 | L | L | (L,L) = ストップ |
| 後進・デューティ 100% | L | H | (H,L) = 正転 |

前進側は**大きさが反転し向きも逆**になる。
とくに「**前進・指令ゼロで全速逆転**」は要件 5.3（ゼロ指令で駆動停止）を
ハードウェアの側で破る挙動であり、E-2（タスク 8.5、開ループ確認）で
モータが暴れる形で現れる。

> 起動直後は `motor_ledc.cpp` が DIR=L・デューティ0 を確定させてから出力を
> 有効化するため (L,L) = ストップであり、要件 5.5 は満たされる。破綻するのは
> **最初に前進が指令された瞬間**である。

#### 決着の候補

| 案 | 内容 | 追加部品 | 評価 |
|---|---|---|---|
| **A** | 外付けロジックで変換。`IN1 = NAND(PWM, DIR)`、`IN2 = NAND(PWM, NOT DIR)`。74HC00 1個／モータ（3個）で足りる | 74HC00 ×3 ＋ 入力プルダウン | 両方向ブレーキ減衰で対称。ただし **BOM 外の IC が3個増える**。未通電時の入力フロートにも対処が要る |
| **B** | **ファームを IN1/IN2 直接駆動へ変える（推奨）。** 2本とも LEDC チャネルにし、前進 = (IN1:PWM, IN2:L)、後進 = (IN1:L, IN2:PWM)、ゼロ = 両方 L | **なし** | 両方向コースト減衰で対称。ゼロ指令＝ストップ。配線は `PWM→IN1 / DIR→IN2` のままでよい |
| **C** | 配線そのまま、ソフトで後進時のみデューティを反転（`1−duty`）する | なし | 前進コースト／後進ブレーキの**非対称減衰**になる。同じデューティで方向により回転数が変わり、速度PID が方向依存のプラントを見る。**推奨しない** |

#### 案B を推した理由と、案B が波及させる先

- 追加部品ゼロ・両方向対称・ゼロ指令がストップ、の3点を同時に満たすのは B だけである。
- LEDC 低速モードのチャネルは8本、3輪×2 = 6本で収まる。
- 変更範囲は `firmware/src/teleop/motor_ledc.cpp` のみで、
  ⚠️ **`lib/drivetrain_control/` には触れない**（tasks.md 冒頭の禁止事項を守れる）。
- ⚠️ ただし `PinRole::kMotorDir` が「素の GPIO 出力であり LEDC チャネルを
  消費しない」という前提が崩れる。`firmware/lib/board_pins/include/board_pins/pin_rules.hpp`
  の `isGeneratorRole` と、LEDC チャネル本数の成立検査（タスク 1.4 / 1.5）に
  見直しが要る。**6本 ≤ 8本なので検査は通るが、判定の定義を直さないと
  「検査が実態を見ていない」状態になる。**
- ⚠️ 名前 `kMotorPwm` / `kMotorDir` が実体と合わなくなる。改名するかは別途判断。

✅ **決着: 案B を採用した（2026-09-21）。**

⚠️ **変わるのは注記だけである。** 配線が動かないぶん、

- エンコーダ出力がオープンコレクタかどうかが未確認である（research.md
  「Risks & Mitigations」）。
- 端子選定は入力専用端子（34〜39）を避けており、内部プルアップを使える
  （`pin_map.hpp` の選定理由）。
- ⚠️ ただし `firmware/src/teleop/encoder_pcnt.cpp` は `pcnt_chan_config_t` に
  プルアップの明示設定を持たない。ESP-IDF の PCNT ドライバが内部で
  プルアップを有効にするかは**版に依存するため要確認**である。
- ✅ **決着: 置く。** 図2b に 10kΩ × 6 を `+3V3` へのプルアップとして
  **破線・未実装**で配置した。実測で必要と判明したときに図を描き直さずに済む。
  ⚠️ **実線で描かないこと。** 破線は「置き場所だけ確保する」という意味である。
