3輪オムニ足回り結線図

LiPo バッテリからモータドライバ3台・ESP32・エンコーダまでを、部品ごとの箱と端子名で描いた図です。 Cirkit Designer で本番の回路図を描くときの下敷きとして使ってください。 IN1 / IN2 の駆動方法は案B（ファーム側で直接駆動）に決着しました。 結線そのものは変わりませんが、線の意味が変わるため図2 の注記まで写してください。

部品は docs/bom.md 準拠 端子番号は kShippedPinPlan 準拠 MCU は classic ESP32（ESP32-WROOM-32） IN1/IN2 駆動 = 案B 決着済み 図1・2・2b・2c・3・4

図の読み方

配線は実際のハーネスの色でそのまま描いてあります。 赤 と 白 がモータの動力線、 青 と 黒 がエンコーダの電源とグランド、 黄 / 緑 がエンコーダのA相・B相です。 灰色は ESP32 からドライバへの制御信号、 橙は 5V 系です。

配線色の罠黒はグランドだが、モータ電源の負側は白である

このモータは 黒＝エンコーダの GND、白＝モータ電源の− です。 「黒＝共通グランド」と読んで 12V 系をエンコーダ対（青・黒）へ入れると、 エンコーダに電源電圧がそのまま掛かって即座に壊れます。 通電前にテスターで色と系統の対応を確かめてください。

電源をどう配るか

バッテリから 12V を1本のバスに立ち上げ、そこからドライバ3台と 5V DC/DC へ分けます。 ESP32 は 5V DC/DC から給電します。

図 1 電源系統 12V バスと接地
JP1 は 5V を切り離すためのジャンパです。 USB を挿して書き込む間は外し、実走行では挿します。BP5293 の 5V と PC の USB 5V が同じ線で並列になるのを防ぐためです。⚠️ 切るのは 5V の1本だけで、GND は常に繋いだままにしてください。
12V は1系統だけです。 バッテリの＋が F1 を通って VM という1本の赤いバスになり、そこから U1・U2・U3・U4 へ分かれます。図の赤い線はすべて同じ 12V です。
SW1 と TB1 は破線＝未決着です。 主電源スイッチと分岐端子の要否・方式は機構側の決定待ちなので、実線で描かないでください。
ESP32 の GND は細い線で GND-STAR まで戻しています。 近くの PGND へ繋がず、C1 のマイナス端子まで1本で引くのが要点です（理由は図4）。
エンコーダの4線はこの図には出てきません。 モータ1個ぶんの詳細は図2 を見てください。

モータ1個ぶんの結線

輪0 を例に、ESP32 ・ モータドライバ ・ モータ＋エンコーダの6線をすべて描いたものです。 輪1・輪2 もまったく同じ形で、GPIO 番号だけが下の表のとおり変わります。

図 2 輪0：ESP32 ─ ドライバ ─ モータ／エンコーダ 輪1・輪2 も同一構成
モータから出ている線は全部で6本です。 太い2本（赤・白）がドライバからの動力、細い4本（青・黒・黄・緑）がエンコーダです。系統がまったく別なので、束ねるときも分けてください。
黄と緑は破線で描いています。 メーカーの記載でも両方とも「信号線」としか書かれておらず、どちらが A相 かは資料を探しても載っていません。実測でしか決まらないので、確定するまで「確定した色」として描かないでください。
VREF と RS はこの図では省いています。 8端子すべての接続は図2bを見てください。VM−GND 直近の 0.1µF セラミックも図2b にあります。
⚠️ 赤と白はどちらも「出力」です。 白は「モータ電源−」という名前ですが H ブリッジの出力端子（OUT2）であり、GND ではありません。逆転中は白に 12V が出ます。 ここへエンコーダの黒を繋ぐとエンコーダが即死します。
案B にしても線は1本も動きません。 GPIO19→IN1、GPIO23→IN2 のままです。変わるのは線の意味だけで、「PWM線と方向線」ではなく「前進時に振る線と後進時に振る線」になります。この注記を省くと図が案B前と区別できなくなります。

決着IN1 / IN2 の駆動は案B — ファーム側を直接駆動へ変える

TB67H450 は IN1 と IN2 の組み合わせで動作が決まる IC です （L,L=ストップ ／ H,L=正転 ／ L,H=逆転 ／ H,H=ブレーキ）。 いっぽう従来のファームは「PWM 1本＋方向レベル 1本」を出していたため、 素直に繋ぐと前進・指令ゼロで全速逆転していました。 これを、どちらの線に PWM を載せるかで方向を表す方式へ改めます。

配線は1本も変わりません。 GPIO19→IN1、GPIO23→IN2 のままで、 追加部品もゼロです（案A の 74HC00 ×3 が要らない）。 前進と後進で減衰の効き方が揃うため、あとで速度制御を載せたときに 方向によって挙動が変わることもありません。

図の側でやることは注記だけです。 配線が変わらないぶん、注記が案B を表現する唯一の手段になります。 図2 の「IN1 ← 前進時に PWM／IN2 ← 後進時に PWM」と、上の表を必ず写してください。 これを省くと、図は案B 前とまったく同じ絵になります。

✅ データシートとアプリケーションノートで裏付けが取れました。 上の真理値表はデータシート p.6 のとおりです。さらにアプリケーションノートには 「4. ダイレクト PWM 制御」という章が独立してあり、 「IN1、IN2 端子に PWM 信号を入力して PWM 動作させることにより速度制御が可能」と明記されています。 案B は許容される使い方ではなく、メーカーが想定している使い方でした。

同じ章が「定電流機能を無効にする場合は RS 端子を GND に接続し、VREF 端子には 1〜5V を入力」 とも述べています。本図は定電流機能を有効のまま使い、電流上限を 1.5A に設定します （理由は「なぜ電流を 1.5A で止めるのか」を参照）。

⚠️ ゼロ指令 (L,L) が 1ms 続くとスタンバイに入りますが、復帰は最大 30µs です。 制御周期 100〜200Hz（5〜10ms）に対しては無視できます。 また IN1 / IN2 には内部 100kΩ プルダウンがあるため、ESP32 が未駆動のときは 自動的に (L,L) = ストップになります。

なぜ電流を 1.5A で止めるのか（安全側に寄せた判断）

前置きデータシートは電流制限を要求していない

制限しない構成も正式に認められています。 「定電流制御機能を無効にしたい場合は、RS 端子を GND に接続し、VREF 端子に 1〜5V を 入力してください」（データシート p.10 ／ アプリケーションノート 4.1）。 0.22Ω は「定電流制御を使う場合の推奨値」として表7-2 に載っているだけです。

1.5A に絞るのは本図の判断であって、データシートの要求ではありません。 以下はその判断の根拠です。

モータのストール電流は 2.3A です。データシートの値で損失を計算するとこうなります。

条件IC の損失許容損失 2.85W に対して
ストール 2.3A（Ron 0.6Ω 標準）3.17 W超える。Ron 最大 0.8Ω なら 4.23W
制限 1.5A（Ron 0.6Ω 標準）1.35 W余裕あり

⚠️ この計算には前提が2つあります。 ひとつは「連続で」2.3A が流れることで、一瞬のストール（数十〜数百 ms）なら 熱容量が吸収します。もうひとつは許容損失 2.85W が4層基板の値であることで、 秋月のモジュール（2層）ではこれより小さくなります。

さらにデータシート自身は 2.45A までを目安として許容しています（注1）。 PD 2.85W とは緊張関係にあり、それを「周囲温度条件や基板条件により、電流がさらに 制限されることがあります」で吸収しています。どちらとも読めるのが正直なところです。

それでも絞るのは、ソフトのモータロック保護の発火試験が開ループ確認より後の段だからです。 その間、IC を守るのはハードの制限しかありません。失敗したときの損失も非対称です — 付けて不要なら約200円と低速トルクが少し減るだけ（線に替えれば戻る）、 付けずに必要なら TSD で断続動作して切り分けが難しくなり、最悪 IC が壊れます。

付けない判断も正当です。 その場合は RS を GND へ直結し、 開ループ確認と M2a-0 でモータを長時間ストールさせない運用 （壁に押し付けない・手で止めない・ドライバが熱ければ止める）を、 ソフトのロック保護を確認するまで守ってください。

VREF に 3.3V、RRS に 0.22Ω を入れると上限が 1.5A になります。 この 0.22Ω はアプリケーションノート 表7-2 が「1.5〜3.0A 用」として挙げている値そのものです。

保護は3段構え
段働くところ解除のしかた
定電流制御（1.5A）常時。電流がここで頭打ちになる—（制限しているだけ）
ソフトのモータロック保護ストールが一定時間続いたら停止ファームの判断
ISD（過電流 4.9A 標準・ラッチ）短絡など異常時電源再投入、または IN1/IN2 を 1ms 以上 L にしてから再指令
TSD（150〜175℃・自動復帰）最後の砦⚠️ データシートは「積極的に活用する使い方は避けよ」と明記

ISD はファームから解除できます。 案Bのゼロ指令 (L,L) を 1ms 以上保持してから 指令を再開するだけです。モータロック保護の復帰を自動にするか手動にするかを決めるときの材料になります。

補足1.5A に絞っても加速性能はほとんど落ちない

DC モータの機械出力が最大になるのは、電流がストールの半分のときです。 本機なら 2.3A ÷ 2 = 約 1.15A。1.5A 制限はこれより上にあるので、 ピーク出力はほぼ無傷です。削られるのは速度ゼロ付近の踏ん張りトルクだけで、 そこは出力（トルク×回転数）としては元々小さい領域です。

副次的に、3輪で 1.5A×3 = 4.5A になるので、10A ヒューズと配線への負担も軽くなります （無制限なら 6.9A）。

⚠️ RRS は「付けるか付けないか」ではありません。 RS は必ず GND へ繋がないと電流の戻り道がなく回路が成立しないので、 選択肢は「その場所に 0.22Ω を入れるか、ただの線を入れるか」です。 配線も基板設計も変わりません。あとから線に替えるのも、VREF を 4.0V まで上げて 1.82A にするのも、半田を1箇所やり直すだけです。

この制限がいちばん効くのはブリングアップの間です。 2.3A が流れるのは壁に押し付けた・車輪が噛んだといった異常時だけで、 本来はソフトのモータロック保護の領分です。ただしその保護の発火試験は 開ループ確認より後の段なので、それまでは IC を守るものがハードの制限しかありません。

部品は酸化金属皮膜 1W 以上（2W なら安心）。セメント抵抗に多い巻線型は避けてください — インダクタンスが電流検出にノイズとして乗ります。 消費電力は制限値いっぱいで 1.5²×0.22 ≒ 0.5W、通常走行ではずっと小さい値です。

⚠️ 上限に当たると固定OFF時間 25µs が割り込むため、 デューティと電流の関係は上限付近でのみ崩れます。上限より下では影響しません。

電源を入れる順序

手順VM を入れる前に、ESP32 の IN1 / IN2 を L にしておく

アプリケーションノートの指示です（1.2 / 3章）。

  • VM 電圧が不安定な立ち上げ／立ち下げの途中は、モータ動作を OFF にしておく
  • 電源投入前は入力信号も Low レベルにしておく

⚠️ これは開ループ確認に直撃します。 USB で ESP32 だけ生かしたまま（VM オフ） IN1 / IN2 が振られている状態で主電源を入れると、入れた瞬間にモータが動きます。 手順として「VM を入れる前に ESP32 をリセットする」を挟んでください。

救いとして、IN1 / IN2 には内部 100kΩ プルダウンがあります。ESP32 がリセット中で 端子がハイインピーダンスなら、自動的に L に落ちてストップになります。

USB を挿すときは JP1 を外す

開ループ確認では USB で書き込みながら、ログを見ながら、モータを回します。 このとき USB の 5V と BP5293 の 5V が同じ線に並列でぶら下がると、 電圧の高いほうが低いほうへ流し込みます。 PC の USB ポートへ逆流するか、BP5293 の出力へ逆流するかのどちらかです。 降圧コンバータは出力側から電流が入ることを想定していません。

JP1 の運用
場面JP15V の供給元
書き込み・ログ確認（USB あり）外すUSB のみ
実走行（USB なし）挿すBP5293-50 のみ

⚠️ 切るのは 5V の1本だけです。GND は常に繋いだままにしてください。 切ってしまうと、ドライバの論理基準と ESP32 の基準が別物になります。

モータの 12V は BP5293 とは別系統なので、JP1 を外しても USB 給電のまま普通にモータが回せます。 DevKit の 5V ピンが USB の VBUS と直結かダイオード経由かは基板の版によって違いますが、 JP1 を入れておけばどちらであっても問題が起きません。

見分け方エンコーダの黒から ESP32 の GND ピンまで、指でたどってみる

その経路にモータ電流が流れる区間があるか。あれば間違いです。

エンコーダは A相 / B相 を「自分の黒を 0V として」出します。 ESP32 はそれを「自分の GND を 0V として」読みます。 この2つの 0V がずれれば、そのずれがそのまま信号に足し算されます。 黒から ESP32 の GND までの経路にエンコーダ自身の消費電流（十数 mA）しか流れていなければ、 ずれようがありません。

⚠️ 効くのは電圧差よりスパイクのほうです。 配線と端子で 20mΩ、6.9A 流れても 138mV 程度で、ESP32 のロジックしきい値には余裕があります。 危ないのは PWM が切り替わる瞬間で、配線のインダクタンス（20cm で約 200nH）に L·di/dt の電圧が立ちます。1A/µs なら 0.2V。 エンコーダの計数はエッジを数えているので、スパイク1発がパルス1個の誤カウントになります。 壊れるのではなく静かに数え間違える故障なので、たちが悪いほうです。

モータの電流は最大で 2.3A × 3 ＝ 約 6.9A 流れます。 この電流が通る線に ESP32 のグランドをぶら下げると、線の抵抗で生じた電圧が そのまま ESP32 の基準電位の揺れになります。

図 4 接地：星形1点で合流させる 左が正・右が誤り
合流点は図の上で1箇所だけにしてください。 2箇所以上で繋がると接地ループになります。GND-STAR から出ている線が何本で、どれが動力側でどれが信号側かが数えられるように描くのがコツです。
ドライバの GND は動力側です。 AE-TB67H450 は GND ピンが1本しかなく、IN1 / IN2 の基準もその GND なので、動力側として扱います。
⚠️ 「黒と白がつながる」ではありません。 接地でつながるのは エンコーダ黒 ─ ESP32 GND ─ ドライバの GND 端子(pin1) ─ C1/C2 の − ─ バッテリ − です。白（OUT2）はこの仲間ではありません。 H ブリッジの出力なので、逆転中は 12V が出ています。
実際の配線でいうと、エンコーダの黒は ESP32 の GND ピンへ挿し、ESP32 の GND から GND-STAR へ1本引きます。避けるべきはドライバの GND 端子に黒を共締めすること、太い動力線の途中に割り込ませることです。

Cirkit Designer で描くときの順序

この図をそのまま写すときの手順です。電源から描き、信号は最後にしてください。 接地の分け方が先に決まっていないと、あとから直すのが最も面倒になります。

  1. 電源系（図1） — BT1 → F1 → VM バス → U1・U2・U3・U4。SW1 と TB1 は破線の箱のまま、実線で繋がない。
  2. 接地（図4） — PGND と SGND を分け、合流は GND-STAR の1点だけ。C1 のマイナス端子を星の中心にする。
  3. 電解コンデンサの向き — C1・C2 の ＋ を VM 側に、記号で極性がわかる形で置く。本機でいちばん危険な部品です。
  4. モータ1個ぶん（図2 と 図2b）を描いて、3回複製 — GPIO 番号だけを14本表のとおり差し替える。
  5. ドライバの8端子を全部繋ぐ（図2b） — VREF→3.3V、RS→0.22Ω→GND、VM−GND 直近に 0.1µF。⚠️ RS と 0.1µF は IC のすぐ横に置くこと。
  6. 案B の注記を書く — 「IN1 ← 前進時に PWM／IN2 ← 後進時に PWM」と真理値表。これを省くと図が案B 前と区別できません。
  7. 電圧監視（図3） — R1 の上端は BAT+ ではなく VM（ヒューズより後ろ）。C6 は GPIO32 ピンの直近。
  8. ノイズ対策部品に置き場所の文字を添える — C3–C5「モータ本体端子に直付け」、C6「GPIO32 直近」、C1/C2「VM−GND ループ最小」。接続先だけでは足りません。
  9. TP1〜TP7 を記号で置き、期待値を併記する — 手順書が「どこを測るか」を文章で説明せずに済むようにするためです。
  10. 未確定・未決着の表示を入れる — 黄/緑、OUT1/OUT2 と赤/白、SW1、TB1、プルアップ。確定値として描かないこと。
  11. MCU が classic ESP32（ESP32-WROOM-32）であることを確かめる — ⚠️ ESP32-S3 では GPIO22/23/24/25 が存在せず、32/33 も使えません。部品を置く前に確認してください。
  12. 14本表と1本ずつ突き合わせる — 「表にあるのに図に無い」と「図にあるのに表に無い」の両方向を見る。
  13. 電源投入の順序を注記する — 「VM を入れる前に ESP32 をリセットする」。入れた瞬間にモータが動くのを防ぐためです。
