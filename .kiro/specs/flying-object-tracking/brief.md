# Brief: flying-object-tracking

## Problem

予測（`prediction-core`）は「時刻付き3D点の列」を要求するが、
**その列を作る手段が存在しない。**

RealSense が返すのは Depth / Color フレームであり、
そこから「飛来する空き缶」だけを取り出し、フレームを跨いで同一物体として繋ぎ、
3D 座標の時系列にする処理が必要になる。

さらに時間制約が厳しい。時間予算表の区間2（検出開始〜予測確定）は **0.10〜0.15 s** しかなく、
その中で FR-1 が要求する最低3サンプルを取り切る必要がある。

## Current State

- 物体検出方式は**未確定**（OQ-26）。**AI モデルを最初から必須にしない**方針だけが確定
- 軽量方式の候補: Depth 差分 / 背景差分 / フレーム間差分 / Motion detection / ROI / 輪郭抽出
- 対象物は**空き缶に固定**（φ65mm 程度の剛体）と決定済み
- コードは一行も存在しない

## Desired Outcome

- 飛来する空き缶を検出し、**3D位置 (x, y, z) の時系列**として出力できる
- 時間予算の区間2 内で**最低3サンプル**取得できる（FR-1）
- 検出方式ごとの**実効サンプル数**（取得できた数 − 取りこぼし）を比較できる
- 人・手・背景などの誤検出を、下流が残差で棄却できる形で渡せる

## Approach

**軽量方式から実測して選ぶ。** 最初から YOLO 等を前提にしない。

対象が空き缶（剛体・形状一定・Depth に写りやすい）に固定されたため、
Depth 差分やフレーム間差分でも十分な可能性が高い。まずそこから測る。

検出方式の比較は **fps 単体ではなく実効サンプル数**で行う。
高 fps は取得サンプルを増やす一方、Pi 4 の処理落ち（dropped frame）を招けば逆効果になる。

追跡（フレーム間の同一物体対応）は、飛翔体が1個・短時間・単調な軌道であることから、
**最初は最小限の実装**でよい。複数同時投擲は対象外。

## Scope

- **In**:
  - 物体検出方式の実測比較と選定（→ OQ-26）
  - 空き缶の検出（Depth 中心を優先。RGB が不要なら使わない）
  - Depth からの3D位置取得
  - フレーム間の追跡（同一物体としての対応付け）
  - 検出〜追跡区間のレイテンシ計測（`development-environment.md §13.1`）
  - ROI による処理範囲の限定
- **Out**:
  - カメラ座標 → World 座標の変換（→ `world-frame-calibration`）
  - 予測・フィッティング（→ `prediction-core`）
  - 落下地点の可視化と時間予算の総合評価（→ `m1-prediction-validation`）

## Boundary Candidates

- **検出**（フレーム → 画像上の候補領域）
- **3D位置取得**（候補領域 + Depth → カメラ座標系の点）
- **追跡**（フレーム間の対応付け → 1投擲の点列）
- **計測**（各段のレイテンシと実効サンプル数）

## Out of Boundary

- **ゴミの種類判別（分別）。** `requirements.md` でスコープ外と明記
- 複数物体の同時追跡。**1投擲＝1物体**を前提とする
- 誤検出の最終的な棄却判断。残差による棄却は `prediction-core` の出力を使って
  `m1-prediction-validation` 側で行う
- 空き缶以外の対象物（ペットボトル・紙くず）への対応。
  OQ-02 の最終決定時に再検討する

## Upstream / Downstream

- **Upstream**: `sensing-foundation`（フレーム取得・入力層抽象・ロギング基盤）
- **Downstream**:
  - `world-frame-calibration`（検出結果を World 座標へ変換する相手）
  - `m1-prediction-validation`（点列を `prediction-core` へ流す）

## Existing Spec Touchpoints

- **Extends**: なし
- **Adjacent**: `world-frame-calibration` と**並行実装できる**。
  本 Spec は**カメラ座標系まで**を持ち、World への変換は持たない。
  **この境界を曖昧にすると誤差の原因を分離できない**

## Constraints

- **AI モデルを最初から必須にしない。** 軽量方式を先に実測する（OQ-26）
- Pi 4 向け設計方針: 低レイテンシ優先 / 必要な **ROI だけ**処理 /
  不要な画像コピーを減らす / **毎フレーム巨大な Point Cloud を作らない** /
  RGB が不要なら **Depth 中心の構成**も検討する
- **fps 単体で評価しない。実効サンプル数で評価する**
- FR-1 の「最低3サンプル」は**絶対値ではない。**
  実用上足りない可能性があり、M1 の実測で見直す前提にする
- 対象物は空き缶（φ65mm 程度）。**この仮値は OQ-02 の最終決定ではない**
