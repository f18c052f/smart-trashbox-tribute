# Implementation Plan

> 本計画は `requirements.md`（要件1〜13 / 受入基準93件）と `design.md` に基づく。
>
> **タスク1〜8 は実機を必要としない。** 上流 `sensing-foundation` の記録済みセッションと、
> テストツリーに置く合成器（既知の3D軌道 → Depth フレーム列）だけで、
> 検出・逆投影・追跡・比較の全経路を実装・検証できる。
> **タスク9 はハードウェア必須**であり、Pi 4 と D435 が揃い、`sensing-foundation` の
> ブリングアップが完了するまで着手できない。**OQ-26 の確定はタスク9で行う。**
> この分割は「実機待ちの期間に何も進まない」事態を避けるための意図的なものである（要件 11.4）。
>
> **上流依存**: タスク6以降は `sensing_foundation` の公開入口（`FrameSource` / `open_source` /
> `Logger` / `SessionReader`）を実際に呼ぶ。上流が未実装の間は、
> テスト用の最小実装（タスク1.5）に対して実装・検証を進める。

## 3. カメラ座標系での3D位置

- [ ] 3. 3D位置: 逆投影と寸法の本判定

- [x] 3.1 候補からカメラ座標系の代表3D点を求める
  - ⚠️ **逆投影の基本演算は自前で書かない。** 無効画素の判定・距離値から mm への換算・画素からカメラ座標への逆投影は、**上流 `sensing_foundation` の公開入口が提供する3つの純関数を呼ぶ**。ピンホールの式・スケール係数の乗算・無効値の直値比較を本モジュールに書かない（`world-frame-calibration` と同一の実装に乗ることが、座標ずれと検出誤差を切り分ける前提である）
  - 本タスクが持つのは**集約方針**である: 候補領域内の**どの画素をどう代表させるか**、候補の絞り込み、内部パラメータ出所の記録、失敗理由の分類
  - 候補の外接矩形内の距離値のうち**測距できなかった画素を上流の判定関数で除外**し、**欠測を 0 や推定値で埋めない**
  - 有効画素が下限未満なら理由付きで無効として返す（例外にしない）
  - 代表距離は外れ値に強い代表値（両側を一定割合切り落とした平均）で求め、ばらつきが上限を超えたら理由付きで無効とする。**この代表値の決め方は本 Spec 固有であり、上流には無い**
  - 代表距離の mm 換算は**上流の換算関数にのみ委ねる**（スケール係数を自分で掛けない。**1カウント = 1mm と決め打ちしない**）
  - 上流の逆投影関数へ、mm 換算済みの距離と候補重心の小数画素座標を渡して**カメラ座標系**の点を得る（**画素中心の規約は上流が持つ。`+0.5` の補正を足さない**）。時刻は上流のフレーム時刻をそのまま引き継ぐ
  - **寸法の本判定**を行う: 実測距離と対象物の想定直径から期待画素直径を導出し、許容倍率の外なら除外して理由を数える
  - 距離帯の外なら理由付きで無効とする
  - **候補の外接矩形の外側を一切読まない**ことと、**全画面の点群を作らない**ことを docstring に明記する
  - 逆投影に用いた内部パラメータの出所を点に記録する
  - 内部パラメータが得られない場合は**推測して続行せず**、専用の例外で失敗する
  - 観測可能な完了状態: 既知の内部パラメータと既知の距離に対して逆投影が解析解と一致し、有効画素不足・ばらつき過大・距離帯外・寸法不一致がそれぞれ対応する理由を返し、**上流の3関数を呼んだ結果と一致する**ことをテストで固定する
  - _Requirements: 2.5, 2.6, 3.3, 5.1, 5.2, 5.3, 5.4, 5.5, 5.6, 5.7, 5.8, 10.1, 10.4, 10.6_
  - _Depends: 1.4, 1.5_
  - _Boundary: PointEstimator_

- [x] 3.2 逆投影の往復を合成入力で検証する
  - 合成器が描いた既知の3D位置を、検出を経由せず候補を直接与えて逆投影し、投入値と一致することを確認する
  - 距離・画像上の位置・対象物直径を変えた複数条件で往復を確認する
  - 処理範囲を変えても復元される3D位置が変わらないことを確認する
  - 合成器の逆演算も**上流の逆投影関数と同じ規約**（画素中心・スケール係数の適用位置）で書き、本 Spec 側だけの規約を持ち込まない
  - 参考: 本 Spec の経路と `world-frame-calibration` の経路が同一入力に対して完全一致することは、`m1-prediction-validation` がクロス Spec 契約テスト（`tests/m1_validation/test_deprojection_contract.py` / 同 Spec 要件 1.10）として強制する。**本タスクはその契約テストを実装しない**が、規約を勝手にずらすと当該テストが落ちる
  - 観測可能な完了状態: 複数条件のすべてで投入した3D位置が許容誤差内で復元され、処理範囲の指定が結果を変えないことをテストで固定する
  - _Requirements: 2.5, 5.1, 5.8, 11.2_
  - _Depends: 3.1_
  - _Boundary: PointEstimator_

## 4. 追跡

- [ ] 4. 追跡: 対応付けとライフサイクル

- [x] 4.1 単一物体の追跡を実装する
  - **1投擲 = 1物体**を前提とし、複数物体の同時追跡を持たない
  - 追跡開始時にそのフレーム時刻を**追跡開始時刻**として記録する
  - 追跡中の点が2点以上あれば直近2点の等速外挿で予測位置を作り、1点なら直前点を予測位置とする
  - 予測位置から許容移動量以内の点を候補とし、最も近い点を採る
  - **距離が同値のときのタイブレークを規則で固定する**（決定的であること）
  - ゲート内に居た他候補の数を点に記録し、ゲートで落ちた件数を数える
  - 対応付け可能な点が無い状態が許容フレーム数を超えたら追跡を終了し、**終了理由を付与する**（欠測超過・入力終了・点数上限・明示的打ち切り）
  - **毎フレーム逐次結果を返す**（追跡終了を待たせない。上流の予測が3点で初回予測を出す設計と整合させるため）
  - 対象物以外の動体を追跡してしまっても**例外にせず**通常の点列として出力する（最終的な棄却判断を持たない）
