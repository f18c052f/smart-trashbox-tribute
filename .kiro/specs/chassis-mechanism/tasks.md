# Implementation Plan

> 本計画は `requirements.md`（要件1〜11 / 受入基準103件）と `design.md` に基づく。
> **中核層（パラメータ・幾何・隙間・接合・観測・記録）は標準ライブラリと上流 `catch_mechanism` の
> 公開 API のみで動く。** 形状ライブラリは上流が導入済みの `cad` 任意依存を使い、
> ⚠️ **新しい extras を追加しない**（許可リストの2ファイルには一切触れない）。
> ⚠️ **上流の実装コード・`src/trajectory_sim/`・`firmware/` には一切触れない。**
> 上流設定への書き戻しは**値と出所のみ**、シミュレータへの還元は**値のみ**で行う。
>
> **物理作業を要するのは 5群・6群のみ**である。1〜4群と7群の大半は、公称値を仮値としたまま
> 完走・検証できる（要件 1.5 / 1.9）。⚠️ **5群の採寸が入ると 2〜3群の導出結果は自動で変わる。
> これは手戻りではなく、設計がそう作られていることの確認である。**
>
> ⚠️ **本計画のどこにもモータへ通電する操作は無い**（要件 9.8 / 9.9）。
>
> **3群と 4.2 / 4.4 は形状ライブラリを導入した環境が要る**（上流が宣言済みの任意依存を有効にする）。
> それ以外のタスクとテストは、⚠️ **形状ライブラリを導入していない環境で完走する**。

## 2. 中核: 幾何・隙間・接合・観測・記録

- [x] 2. 中核: 幾何・隙間・接合・観測・記録

- [x] 2.1 幾何の導出と導出記録の直列化を実装する ⟨2.2 のレビューを受けて鉛直スタックを修正済み⟩
  - ホイール配置半径を「機体中心から取付面までの距離」と「取付面からホイール中心までの実測距離」の
    和として導出する。⚠️ **この導出をここ以外に置かない**
  - 各輪の取付角を等配置で生成する。⚠️ **基準は機体 +x から反時計回りとし、
    輪番号と符号の対応を設計側で定義し直さない**（制御ロジック側の定義が唯一の正である）
  - 接地点を原点とする鉛直スタック（実効転がり半径・車軸中心・モータ胴体下面・取付面・締結の下端）を
    組み立て、高さが逆転する入力を拒否する
  - 軸方向の積み上がりを導出し、後の実測との照合に使える形で保持する
  - 搭載物の質量と保持高さから合成重心の見積もりを導出し、転倒余裕を算出する。
    ⚠️ **「合否条件ではない」ことを型と記録の両方に明示する**
  - アームが成立しない配置半径を形状不正として拒否する
  - 導出記録を、入力・式・出所・結果を持つ形で書き出す
  - 観測可能な完了状態: 取付面までの距離を変えると配置半径・アーム長・鉛直スタックが追随し、
    高さが逆転する入力とアームが成立しない入力が拒否されることをテストで固定する。
    ⚠️ **「取付面までの距離」は2つある。** 機体中心からの距離（半径方向）が配置半径と
    アーム長を動かし、接地点からの距離（鉛直）が鉛直スタックを動かす。
    半径方向の距離が鉛直スタックを動かすことはない（幾何的にあり得ない）
  - _Requirements: 3.1, 3.2, 3.3, 3.5, 3.6, 4.1, 7.8, 7.9_
  - _Depends: 1.4_
  - _Boundary: Layout_

- [x] 2.2 床との隙間の算出と違反の列挙を実装する

  - ⚠️ **例外を送出せず、違反を全件まとめて値として返す**（1件ずつ直す往復を避けるため）
  - 隙間の下限は寸法パラメータから読む。⚠️ **数値をコードへ埋め込まない**
  - 観測可能な完了状態: 実効転がり半径を小さくすると5部位すべての高さが追随し、
    下限を下回った部位が**部位名と不足量つきで全件**返ることをテストで固定する

  - _Boundary: Clearance_

- [x] 2.3 (P) 接合部の定義と締結部品の数え上げを実装する

  - 荷重を受ける締結要素と位置決めのみを担う要素を**型の上で区別**し、
    位置決め要素を当たり面の面積に算入しない
  - 当たり面が上流の下限と本 Spec のより厳しい下限の**両方**を満たすことを、上流の検査を用いて確認する
  - 各接合部が「接合面の法線が積層方向と一致しない」ことを表明する軸を持ち、
    ⚠️ **積層方向と一致する配置を形状不正として拒否する**
  - 分割数の導出を部品の種類で分ける: **円環部品は上流の分割数導出**を用い、

  - 締結部品の長さを「積み上がり厚さ＋上流が定めるインサート長＋余裕」から導出し、

  - 観測可能な完了状態: 積層方向と一致する接合面が拒否され、位置決め要素が締結部品一覧に現れず、
    板厚を変えると締結部品の長さが追随することをテストで固定する

  - 実測重量・重心（高さと半径方向の偏りと測定手順）・ホイール3個の実効転がり径と代表値・

  - ⚠️ **設計入力の設定ファイルとは別のファイルに置く**（形状の再生成が観測のたびに要求されないため）
  - 代表値は3個の平均とし、⚠️ **平均と一致しない記録を整合不一致として拒否する**
  - 測定手順が転動を伴わない場合、⚠️ **その測定が捉えられない範囲の記述を必須にする**
  - 隙間の観測の部位名が、算出側の5部位と一致しない記録を拒否する
  - 必須項目が未記入または仮値のまま残っているものを列挙し、
    ⚠️ **その一覧が空であることを組立完了の定義とする。判定にモータへ通電する項目を1つも置かない**
  - 記録ファイルの初期状態を**全項目が未記入の形**で追加する。
    ⚠️ **6群の実測が始まる前から読み込めるようにする**（読み込み自体が失敗すると、

  - 観測可能な完了状態: 部位が1つ欠けた記録・代表値が平均と食い違う記録・転動を伴わない測定で
    限界の記述が空の記録が、いずれも完了と判定されず、
    **初期状態の記録が読み込めて未記入項目が全件列挙される**ことをテストで固定する
  - _Requirements: 9.8, 10.5, 10.9_
  - _Depends: 2.2_
  - _Boundary: Assembly_

- [x] 2.5 (P) 形状指標の記録の書き出しと識別子照合を実装する
  - ⚠️ **形状指標の型と照合は上流から借り、書き出しだけを実装する**（上流は書き換え操作を公開していない）

  - 記録に埋め込まれた識別子と現在の寸法パラメータの識別子が食い違う場合に、整合不一致として拒否する

## 3. CAD 層: 部品の形状と生成物

> ⚠️ **3群のサブタスクは同一の形状モジュールを編集するため並行実行しない。**
> 部品ごとに独立して見えても、ファイル競合が起きる。
> ⚠️ **整備スタンドを最初に置く。** 要件 5.1 は設計・造形・検証のすべてで先行することを求めており、
> スタンドの設計入力は配置半径と現物採寸値だけで足りる（駆動ベースの形状を待たない）。

- [x] 3. CAD 層: 部品の形状と生成物

- [x] 3.1 整備スタンドを構築する
  - 支持を**駆動ベース端部にぶら下がる駆動ユニット（モータ胴体）の下面**で行う形にする。
    ⚠️ **駆動ベース下面での支持を前提にしない**（そこにはブラケット・締結の頭・配線が並ぶ）
    ⚠️ ホイール外側・駆動ベース端部のいずれも支持面として成立しない根拠を要件 5.3 に記録する
  - **3脚独立**とし、1体の枠にしない（造形可能寸法を超え、一人での載せ降ろしが難しくなるため）
  - 3輪すべてが床にも台にも触れない持ち上げ高さと、ホイールが自由に回転できる隙間を確保する
  - 反力に対して機体が外れないよう、脚がホイールを両側から挟む形の拘束を与える
  - 台上でホイールの回転方向が目視でき、配線・コネクタ・電源の操作部へ手が届く形状にする
  - 設計入力を配置半径と現物採寸値に限り、⚠️ **ゴミ箱とトレイ類の確定を待たない**
  - 観測可能な完了状態: 台に載せた状態で3輪の最下点が床面より上にあり、ホイール外周と台の隙間が
    寸法パラメータと一致し、支持面が駆動ベース下面と接触しないことをテストで固定する
  - _Requirements: 5.1, 5.2, 5.3, 5.4, 5.5, 5.6, 5.8_
  - _Depends: 2.1_

- [x] 3.2 駆動ベース（中央部と3つのモータ取付部）を構築する
  - 中央部と、そこから放射状に伸びる3つのモータ取付部を、幾何の導出結果から構築する
  - ブラケット取付穴を長穴とし、吸収できる寸法差の量を寸法パラメータから読む
  - ⚠️ **造形部品でモータ本体を直接クランプしない。** 付属金属ブラケットを介して取り付ける形にする
  - 接合部は貫通する締結要素と金属インサートと当たり面で構成し、樹脂へ圧縮以外の荷重を主として負わせない
  - 常時荷重がかかる部位は断面を厚く取り、⚠️ **薄いリブや小さな当たり面で受けない**

  `ConsistencyError` を送出する。⚠️ **どちらの公称値に対する差なのかが決まらない数**を
  要件 10.4 の記録として出さないためである
- **UTF-8 でない設定ファイルを終了コード 2 へ写した（指摘6）**: `UnicodeDecodeError` は
  `ValueError` の一種で ⚠️ **`OSError` ではない**ため、`main` の `except` を素通りして
  終了コード 1（検査の不一致・違反）＋追跡情報になっていた。本 Spec の設定ファイルは日本語を含み、
  Windows の編集器が CP932 で保存する経路は現実にある。⚠️ **1 に落ちると CI が「読めないファイル」と
  「乖離した形状指標」を区別できない**。`EXIT_CODE_BY_ERROR` と `main` の `except` の両方へ加え、
  `_read_json_document` は**どのファイルが読めないのか**を残すため `ParameterError` へ包み直す
- **終了コード表の取りこぼし検査を上流の階層へも広げた（指摘8）**: 本 Spec の `errors.__all__`
  だけを見ていたため、⚠️ **上流が7つ目の系統を足したとき、それは表に無い例外として既定（2）へ
  黙って落ちる**。現在の上流6系統がすべて表にあることを固定した
- **7.1 へ（⚠️ 6.7 が代表値を記入すると2つの検査が落ちる）**: 落ちるのは
  `test_the_shipped_simulator_config_agrees_with_the_current_geometry`（還元がまだであるため。
  これが 7.1 の着手の合図である）と、⚠️ **`test_the_entry_point_reproduces_the_shipped_record_byte_for_byte`**

  代表値が入れば実効転がり半径と鉛直スタックが動くため、⚠️ **6.7 は `layout.json` の再生成

### 手作業を前提とした是正（利用者の指摘・2026-09-07）

⚠️ **切断と穴あけは工作機械ではなく手で行う。** それを踏まえて2点直した。

- **底の切り取り径を独立した寸法パラメータへ**（`adapter.bottom_cut_diameter_mm`、
  出荷値 Ø160、上限は上流の平面部径 Ø170）。旧実装は上限をそのまま導出しており
  縁が 5mm しか残らなかった。⚠️ **誤差の効き方は片側である**——小さく切れば縁が
  広がるだけだが、Ø180 まで大きく切ると縁が消える。掴み面は r=60.4〜91 に
  連続しており、⚠️ **Ø121〜Ø176 のどこで切っても縁は載る**
- **溝で縁を挟む案を採らない理由が確定した**。⚠️ **溝は縁の幅に依存し、
  その幅こそ手切りが不確かにする量**である。貫通ボルトは縁の幅を見ないため、
  手作業の不確かさを一箇所に閉じ込められる。側壁の穴は
  ⚠️ **アダプタを組んでからその穴をガイドに開ける**（要件 6.13）ので、
  手作業に残るのは「ドリルをまっすぐ持つ」だけになる。
  ⚠️ **6.5 の「溝で置き換えられるか判断する」という申し送りは取り下げる**
- **組立順が幾何的に成立しないことが判明し、直した**。⚠️ **缶を段の上から
  被せることはできない**（基板デッキ Ø173.6・受け止めデッキ Ø185.4 に対し
  切り口は Ø160）。缶が先、段は缶の口（Ø210）から落とし込む。
  ⚠️ **「組み上がった状態で干渉しない」ことは組み上げられることを意味しない**——
  要件 7.14 として、既に置かれた部品と干渉せずに所定位置へ到達できることを
