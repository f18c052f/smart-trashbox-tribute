# Brief: chassis-mechanism

## Problem

**足回りの部品はすべて手元にあり、制御ロジック（`drivetrain-core`）も実装完了している。
しかし、それらを組み立てて機体にするための構造物が一つも存在しない。**

`teleop-bringup`（M2a 初通電走行）は実機必須の Spec だが、その前提となる物理的な機体が無いため
着手できない。とくに **整備スタンド**は `bom.md §E` が「**M2a-0 で必要**」と明記しており、
`drivetrain-spec.md §11` の台上確認 #15〜#18（回転方向・エンコーダ符号・デッドマン解放・
コントローラ圏外での停止）は**ホイールを床から浮かせた状態でしか安全に実施できない**。
接地したまま初通電すると、極性が逆のまま機体が予期せず走り出す。

**つまり整備スタンドは、駆動系トラック全体のクリティカルパス上にある単一の造形物である。**

加えて `drivetrain-spec.md §6.3` は最低地上高の余裕が小さいことを警告している:
60mm ホイール → 車軸中心高さ約 30mm、モータ径 37mm（半径 18.5mm）→
モータ胴体下面は床から**約 11.5mm**。ブラケット・ボルト頭・フレーム下面・配線の
いずれかが床に触れれば走行そのものが成立しない。

## Current State

- **部品は揃っている**: 60mm ダブルオムニ ×3、6mm ハブ ×3、
  JGB37-520（付属金属ブラケット付き）×3、AE-TB67H450 ×3、3S LiPo、ESP32 DevKit、
  BP5293-50、その他電子部品。**ハード待ちではない**
- **`drivetrain-core` は実装完了**（全41タスク。`decisions.md` D-10）。
  `firmware/lib/drivetrain_control/` に逆運動学・速度PID・オドメトリ・保護①〜④が存在する
- **構造物は一つも無い**。駆動ベース、ゴミ箱固定アダプタ、バッテリートレイ、基板トレイ、
  整備スタンドはいずれも「3Dプリント（自作）」と `bom.md §E` に列挙されているだけで、CAD が無い
- `drivetrain-spec.md §6.4` は「モータ到着後に**仮組みして実寸を測定してから** CAD を完成させる」
  という手順を定めている。部品が揃った今、**この手順が実行可能な状態にある**
- 未決事項が4件係属中: **OQ-07**（フレーム外形＝ホイール間隔）、**OQ-09**（M3ネジ・
  熱圧入インサートの必要数と長さ）、**OQ-11**（メイン電源スイッチの取付位置・要否）、
  **OQ-12**（電源分岐端子の要否と方式）。OQ-11 / OQ-12 は期限が「**機構設計時**」と書かれており、
  本 Spec が唯一の決着先である

## Desired Outcome

- **`teleop-bringup` が着手できる状態になる。** 機体が組み上がり、整備スタンドの上で
  ホイールを浮かせて安全に初通電できる
- **OQ-07 / OQ-09 / OQ-11 / OQ-12 が決着している**
- `drivetrain-spec.md §11` の実機確認 **#1（付属ブラケット実寸）/ #2（取付穴の寸法・ピッチ）/
  #3（最低地上高）**が実測され、CAD に反映されている
- **A1 mini の 180mm 制約下で、モータ反力を受けても成立する分割・接合設計**が確定している
- 機体の**実測重量と重心位置**（§11 #12 / #13）が測れる状態になり、`m2-motion-validation` と
  `catch-mechanism` の概算を実測で置き換える口ができている

## Approach

`catch-mechanism` が確立した CAD 基盤（build123d で形状の正、FreeCAD で組立確認・干渉チェック・図面）
と A1 mini の造形前提をそのまま使い、形状設計に専念する。

**分割方針**: 3輪オムニの駆動ベースは φ250〜300mm 見込みであり、A1 mini の 180×180×180mm には
入らない。円は正方形の対角線（254mm）を利用できないため**斜め配置でも不可**であり、**分割は回避不能**。
`drivetrain-spec.md §6.2` が既に「中央プレート＋3つのモータ取付部の**モジュラー構造**」と
書いているとおり、**中心ハブ＋放射状に3本のモータアーム**という分割が構造的に自然である。

⚠️ **接合部の設計規律**: FDM は XY 面内強度 >> Z 方向（層間）強度で異方性が強く、分割接合部は
必然的に応力集中点になる。**ダボ・蟻継ぎのような「樹脂だけで荷重を渡す継手」は層間剥離モードで落ちる。**
モータ反力（曲げ・ねじり）を受ける継手は **貫通ボルト＋金属ヒートインサート＋広い当たり面で、
樹脂を圧縮のみで使う**設計とし、**ダボは位置決め専用と割り切る**。
接合面の法線が層方向と一致する配置は禁忌。

**現物採寸を先に済ませる**: `drivetrain-spec.md §6.4` の手順どおり、モータ／付属ブラケット／
6mm ハブ／60mm オムニホイールを**仮組みして実寸を測定してから** CAD を完成させる。
測定値は `catch-mechanism` が設置したパラメータの単一の正へ流し込む。
⚠️ **現時点で穴ピッチ等を数値で確定させない**（同 §6.1）。
ブラケット固定穴は**長穴（スロット）化**して寸法差を吸収する。

⚠️ **【MUST】ホイール／ハブは Nexus 純正品ではない**（14145 / 18020 **相当品**。2026-08-30 判明）。
スペックはほぼ同等とされるが、**公称値を CAD にもコードにも入れない。**
以下は本 Spec が実測して確定させる（`drivetrain-spec.md §11 #4a / #4b / #4c`）:

- **実効ホイール径**（3個の個体差も測る）。⚠️ 公称 60mm でも実測 58.5mm なら **2.5% の系統誤差**になり、
  オドメトリ（FR-6）と `trajectory_sim` の **`wheel_diameter_mm`（`configs/trajectory_sim/drivetrain-wheel60.json`）
  の両方へ効く。** 機構だけの問題ではない。⚠️ **「予測は合っているのに届かない」という
  最も切り分けにくい形で現れる**
- **ハブ穴が D 形状か丸穴か。イモネジの効き。** ⚠️ 丸穴だとイモネジだけでトルクを受けることになり、
  **「エンコーダはカウントしているのに機体が進まない」空転**が起きる。**制御側からは検出できない**
- ホイール取付穴のピッチ、ローラー数・ローラー材質（グリップと転がり抵抗 → §11 #8 の前提）

**整備スタンドを先に出す**: 他のどの造形物よりも先に整備スタンドを完成させる。
`teleop-bringup` のクリティカルパス上にあり、かつ最も単純だからである。
⚠️ 最低地上高が小さい構成のため、**フレーム下面ではなくホイール外側または駆動ベース端部で
支持する形状**にすること（`bom.md §E`）。

**モータは付属金属ブラケット経由で固定する**（`drivetrain-spec.md §6.1` の標準案）。
3Dプリント部品でモータ本体を直接クランプしない。

## Scope

- **In**:
  - **駆動ベース**（中央プレート＋モータ取付部3箇所のモジュラー構造。180mm 分割・接合設計を含む）
  - **ゴミ箱固定アダプタ**（`catch-mechanism` が確定させたゴミ箱の底寸法を入力とする）。
    ⚠️ **実売品はほぼ全品がネスティング前提の円錐台である**（例: 上φ220 → 底φ158、片側 約7°）。
    **「円錐台を受ける座」として設計する。円筒前提で設計すると合わない**（2026-08-30 の実売調査）
  - **バッテリートレイ**（低重心化のため最下部配置）、**基板トレイ**、配線ガイド
  - **整備スタンド**（M2a-0 の前提。最優先で出す）
  - **最低地上高の検証**（ブラケット・ボルト頭・フレーム下面・配線が床に接触しないこと）
  - 現物採寸（§11 #1 / #2 / #3）とパラメータへの反映
  - OQ-07 / OQ-09 / OQ-11 / OQ-12 の決着
  - 実測重量・重心位置（§11 #12 / #13）を測る手順の確立
  - **【MUST】非純正ホイール／ハブの実測**（実効ホイール径・ハブ穴 D 形状・取付穴ピッチ。§11 #4a〜#4c）と、
    **実効ホイール径の `trajectory_sim` 設定への還元**
- **Out**:
  - **CAD 基盤そのもの**（ツールチェーン・パラメータの単一の正・ヘッドレス検証）→ `catch-mechanism`
  - **ゴミ箱本体の選定と開口寸法**（FR-7 / NFR-5）→ `catch-mechanism`
  - **緩衝ライナー**（OQ-10。M3 で実投擲後に判断）
  - **通電・走行・計測**（→ `teleop-bringup` / `m2-motion-validation`）。
    ⚠️ **本 Spec は「組み上がって安全に台上へ載る」までを持ち、モータを回さない**
  - センサー固定治具（壁/三脚マウント）。固定側の設置形態 OQ-06 が未決であり、
    駆動系トラックとは無関係。別途判断する
  - フレーム剛性の実測（§11 #11）— 走行させないと共振は見えないため `m2-motion-validation` 側

## Boundary Candidates

- **整備スタンド** — 他から独立して先に出せる。`teleop-bringup` のクリティカルパス
- **駆動ベース（分割・接合・最低地上高）** — 構造の中核。現物採寸に依存する
- **搭載物のトレイ類（バッテリ・基板・配線）** — 駆動ベース確定後
- **ゴミ箱固定アダプタ** — `catch-mechanism` の出力に依存する唯一の部位

## Out of Boundary

- ⚠️ **「組み上がった」ことをもって M2a を達成したと呼ばない。** M2a は初通電走行であり、
  `teleop-bringup` の所有である
- ⚠️ **`DrivetrainParams`（最高速度・加速度上限・減速度上限）の値を決めない。**
  本 Spec は機体の物理的な形と重量・重心を作るだけで、性能値は `m2-motion-validation` の実測が決める
- 制御ロジック（逆運動学・PID・保護）は `drivetrain-core` が実装済み。触れない

## Upstream / Downstream

- **Upstream**:
  - `catch-mechanism` — CAD 基盤、A1 mini 制約の明文化、ゴミ箱の底寸法
  - `docs/drivetrain-spec.md` §6（機構設計）/ §11（実機確認事項）、`docs/bom.md §E`
  - `drivetrain-core`（実装完了）— 機体が満たすべき制御上の前提（ホイール配置・輪番号の規約）
- **Downstream**:
  - `teleop-bringup` — **本 Spec の完了が着手条件**。とくに整備スタンド
  - `m2-motion-validation` — 実測重量・重心を性能評価の文脈として使う

## Existing Spec Touchpoints

- **Extends**: なし
- **Adjacent**:
  - `teleop-bringup` — 同 brief が Out of Boundary とした「ゴミ箱本体・固定アダプタの設計」のうち、
    **固定アダプタ側を本 Spec が引き取る**。⚠️ 逆に本 Spec は通電を一切行わない
  - `drivetrain-core` — ホイール配置（3輪120°）と輪番号の規約が既に実装に埋まっている。
    **CAD 側で番号や回転方向を勝手に定義し直さない**

## Constraints

- **造形機は Bambu Lab A1 mini**。180×180×180mm → **φ180 超の部品は分割必須**。
  エンクロージャ無し・ベッド上限 80℃ → **ASA / ABS / PC / CF・GF は公式に not recommended。
  PETG が実質の上限材料**。⚠️ 荷重部材で最も欲しい ASA が選べないことを設計の初期前提とする
- ⚠️ **PLA は Tg 以下でも常時荷重下でクリープする。** 2kg 級機体を支える構造部材に使うと
  時間経過で垂れる。PETG も耐クリープ性は高くない。**荷重が常時かかる部位の材料選定は
  この事実を前提に決める**
- **最低地上高の余裕は約 11.5mm しかない**（`drivetrain-spec.md §6.3`）
- **金属切削加工は行わない**（CON-1）。**モータ本体を3Dプリント部品で直接クランプしない**（§6.1）
- **バッテリは最下部配置**（低重心化、`requirements.md §5`）。
  安全のためバッテリ直近に 10A メインヒューズを置く
- ⚠️ **現時点で穴ピッチ等を数値で確定させない**（§6.1）。仮組み実測後に確定し、長穴で差を吸収する
- `tech.md` 開発標準1: **未実測の値を合否条件にしない**
