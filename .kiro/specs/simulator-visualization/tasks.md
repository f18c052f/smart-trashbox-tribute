# Implementation Plan

> 本計画は `requirements.md`（要件1〜8 / 受入基準52件）と `design.md` に基づく。
> **実行時のサードパーティ依存はゼロ、開発時依存は TypeScript コンパイラ 1 個のみ。**
> すべてのタスクはハードウェア非接続・ネットワーク非接続で完了・検証できる。
> **ブラウザ側に物理・予測・掃引・成立判定を書かない。** 数値が必要なら上流の JSON に載っている値を使う。
>
> ⚠️ 本 Spec はロードマップ上**先送り可・急がない**と位置付けられており、
> `docs/original-features.md` は「可視化に時間をかけすぎて結論が出ない」失敗を警告している。
> **タスク数が少ないことは弱さではなく設計目標である。**
> 機能を足したくなった場合は実装せず、`design.md` の「先送り事項」へ追記する。

## 1. 基盤: プロジェクト骨組みと共有部品

- [ ] 1. 基盤: プロジェクト骨組みと共有部品

- [ ] 1.1 表示レイヤのプロジェクトを追加し、ビルドとテストが動く状態にする
  - 開発PC のブラウザ向けに、実行時依存を持たない TypeScript プロジェクトを新設する。**実行時依存の欄は空のまま維持する**
  - 型検査を厳格設定にし、コンパイル出力をブラウザが直接読める ES モジュールとする。バンドラ・フレームワーク・CSS フレームワークを導入しない
  - テストランナーは Node.js 組み込みのものを使い、コンパイル済みの出力に対して実行する。実験的機能に依存しない
  - 単一の HTML と最小限のスタイルシートを置き、図の色をカスタムプロパティとして定義する
  - 改行コード規約に新しい拡張子とパッケージ定義ファイルの指定を追加し、依存物とビルド出力を版管理の対象外にする
  - **上流 Python 側のパッケージ設定に触れない**（実行時依存が空であることを上流のテストが検査している）
  - 観測可能な完了状態: ハードウェア非接続の環境でビルドとテストの一連が成功終了し、静的ファイル配信のみで空の画面がブラウザに表示される
  - _Requirements: 7.4, 8.1, 8.2, 8.3, 8.5_

- [ ] 1.2 (P) 入力 JSON の型・列挙値・必須項目の宣言を用意する
  - 上流の出力形式の最上位項目、格子点、掃引定義、較正情報、除外要因、記録の各構造を型として宣言する
  - **上流のフィールド名をそのまま使う。** 読みやすさのための改名を行わない
  - **読む項目だけを型に書く。** 読まない項目を型へ書かない
  - 状態・評価対象外理由・較正段階・出所・掃引種別・予測の種別を、上流が用いる値そのままの列挙として宣言する
  - 必須項目の一覧と、想定する出力形式の版・記録スキーマの版を定数として持つ。**代表記録を必須項目に含めない**
  - パラメータ全体は任意の入れ子として受けられる汎用の値型で表現する
  - 観測可能な完了状態: 型と定数のみを含み関数を公開しないモジュールが追加され、型検査が通る
  - _Requirements: 1.2, 1.4_
  - _Boundary: Schema_

- [ ] 1.3 (P) 値域から画面座標への線形写像と、唯一の補間実装を用意する
  - 値域から画面座標への線形写像、値の並びからの値域算出、余白付与を実装する
  - 始点と終点の間を線形に補うただ 1 つの補間関数を、このモジュールにのみ置く
  - **非線形の写像（対数・平方根・三角関数）を持たない。** 補間パラメータは 0 から 1 に丸める
  - 値域の幅がゼロの場合にゼロ除算を作らない
  - 観測可能な完了状態: 端点で写像が厳密一致すること、幅ゼロの値域で破綻しないこと、補間が中間点で中央値を返すことを検証するテストが通る
  - _Requirements: 2.1, 5.6_
  - _Boundary: Scale_

- [ ] 1.4 (P) 画面に出る文言の生成を 1 箇所に集約する
  - 上流の列挙値から表示名への対応表を、このモジュールにのみ置く
  - 数値を単位付きで表示する関数、軸の値・指標のキー・無効理由を表示名へ変える関数を用意する
  - **未知のキー・未知の理由はそのまま返す。** 表示できない情報を握りつぶさない
  - **合否・達成・NFR-7 の充足に相当する断定語を生成しない。** 上流の語を判定語へ読み替えず、補足を添える形にする
  - 観測可能な完了状態: 公開関数の全戻り値に断定語が含まれないことを走査するテストと、未知のキーがそのまま返ることを検証するテストが通る
  - _Requirements: 2.3, 2.9, 3.6, 5.4_
  - _Depends: 1.2_
  - _Boundary: Format_

## 2. 入力の読み込みと検証

- [ ] 2. 入力の読み込みと検証

- [ ] 2.1 テスト用の最小入力を生成する仕組みを用意する
  - 上流の出力形式に沿った、必須項目をすべて備えた最小の掃引結果を生成する関数を用意する
  - 1 軸 / 2 軸 / 3 軸の掃引、成立・不成立・評価対象外の混在、代表記録を含む場合と含まない場合の各入力を作れるようにする
  - 代表記録には有効な予測と無効な予測の両方を含め、上流の予測種別の値をそのまま用いる
  - **ファイルシステムを使わない。** テストから直接呼べる値として生成する
  - 観測可能な完了状態: 生成した最小入力が、宣言済みの型と必須項目一覧に矛盾しないことを検証するテストが通る
  - _Requirements: 1.2_
  - _Depends: 1.2_
  - _Boundary: tests fixtures_

- [ ] 2.2 検証済みの表示用ビューを作る読み込みを実装する
  - テキストとファイル名を受け取り、解釈・必須項目の検証・型の検証・列挙値の検証を行って、検証済みのビューまたは問題の一覧を返す
  - **必須項目が 1 つでも欠けていれば失敗として返す。** 部分的に描ける状態を作らない
  - 欠落・型不一致は**最初の 1 件で打ち切らず、すべて列挙する**
  - 未知の列挙値は失敗として扱う（黙って「その他」に丸めると上流の変更が表示側で見えなくなる）
  - 出力形式の版の不一致は**警告として返し、読み込みは成功させる**
  - 代表記録が無い / 配列でない / 要素が読めない場合は、読み込みを成功させたうえで記録側の問題として返す
  - **入力に無い値を作らない。** 既定値の補完・推定・単位換算を行わない。ファイル読み出しと通信を行わない
  - 観測可能な完了状態: 必須項目を 1 つずつ落とした入力がすべて失敗し欠落項目名が現れること、解釈不能な入力・版不一致・記録欠如がそれぞれ設計どおりに扱われることを検証するテストが通る
  - _Requirements: 1.2, 1.3, 1.4, 1.5, 1.7_
  - _Depends: 2.1_
  - _Boundary: Loader_

## 3. 表示プランの生成

- [ ] 3. 表示プランの生成

- [ ] 3.1 (P) キャッチ可能領域のプランを実装する
  - 掃引の軸から最大 2 軸を描画に使い、格子点を軸の値の並び順で等間隔に配置するプランを組み立てる
  - **判定を行わない。** 状態は上流の値をそのまま用いる
  - 状態と成立割合の帯に対応する分類キーを返し、**実際の色を決めない**
  - 評価対象外を不成立と異なる分類キーで表し、理由を格子点の詳細文へ含める
  - 格子点の詳細文に軸の値・状態・成立割合・指標を含める
  - 軸が 3 本以上のときは残りの軸を固定値で絞り込み、固定している軸と値をプランへ含める。軸が 1 本のときは 1 行の並びにする
  - 凡例に、上流の判定閾値と**表示上の帯の境界**を区別して含め、試行回数を併記する。色分けが表示上の取り決めであり合否条件ではない旨をプランへ含める
  - **格子点の間を補間して滑らかな境界を描かない**（上流が評価していない点の値を作ることに等しい）
  - 観測可能な完了状態: 2 軸掃引の格子点数が軸の値の積に一致すること、評価対象外が不成立と別の分類キーを得ること、3 軸掃引で固定軸が絞り込みとして働くこと、1 軸掃引が 1 行になること、凡例に閾値と表示上の帯の両方が現れることを検証するテストが通る
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.5, 2.6, 2.7, 2.8, 2.9, 3.5_
  - _Depends: 2.2_
  - _Boundary: RegionPlanner_

- [ ] 3.2 (P) 前提・限界・同一性のプランを実装する
  - 較正段階と、存在する場合の注意書きを常時提示できる形で返す
  - モデル除外要因を**段ごとに全項目**返す。件数だけの要約に置き換えない
  - パラメータ全体をドット区切りのパスへ平坦化し、出所の対応表と突き合わせる。平坦化は構造のみに基づき、パラメータの意味を知らない
  - **出所の記載が無い行を「想定」で埋めない。** 記載が無いことを記載が無いまま表す
  - 機体パラメータを、パスの前置きによる抽出のみで取り出す
  - ファイル名・出力形式の版・掃引種別・軸・試行回数・乱数種・判定閾値を同一性の行として返す
  - 読み込み時の警告を提示対象へ含める
  - 観測可能な完了状態: 除外要因が 1 つも落ちないこと、平坦化したパスが出所の対応表と突き合うこと、記載の無い行が「記載なし」として表れること、機体パラメータが抽出されることを検証するテストが通る
  - _Requirements: 1.6, 3.1, 3.2, 3.3, 3.4, 3.5, 4.1, 4.2, 4.3_
  - _Depends: 2.2_
  - _Boundary: ContextPlanner_

- [ ] 3.3 (P) 軌跡アニメーションのプランを実装する
  - 代表記録から、床面を真上から見た投影と、水平方向と高さの投影の 2 種類のプランを組み立てる
  - 予測を生成順に並べ、有効な予測は予測落下地点と基準サンプル数を、無効な予測は理由と詳細を持たせて**両者を区別できる形**にする
  - 任意時刻のフレームを返す仕組みを実装し、現在位置は**隣り合う 2 つの観測点の線形補間のみ**で求める
  - その時刻までに得られている最後の予測を選び出す。**予測を計算し直さない**
  - **記録に無い量を作らない。** 移動体の位置・真の軌道・記録範囲外への外挿を返さない
  - 観測点を並べ替えない（並んでいなければ上流の問題である）。観測点が 0 件の記録でも破綻しない
  - 観測可能な完了状態: 2 点の中間時刻で現在位置が中点になること、無効な予測が落下地点を持たず理由を持つこと、選ばれる予測が時刻条件を満たす最後のものであること、観測点 0 件で破綻しないことを検証するテストが通る
  - _Requirements: 5.1, 5.2, 5.3, 5.4, 5.6, 5.7_
  - _Depends: 2.2_
  - _Boundary: AnimationPlanner_

## 4. 描画と画面の結線

- [ ] 4. 描画と画面の結線

- [ ] 4.1 プランをベクタ図と表へ写す描画層を実装する
  - キャッチ可能領域・前提と限界・同一性・読み込み失敗の各プランを、ベクタ要素と表として描く
  - **プランに無い判断をしない。** 位置・文字列・分類はすべてプランが決めている
  - 格子点の詳細はベクタ図の標準的な補助要素として与え、**独自のツールチップ機構を作らない**
  - 分類キーをクラス名へ写すだけにし、色はスタイルシート側に置く
  - 再生用の描画は、要素を作ってから各フレームでは**属性の更新のみ**を行う形にする。毎フレームの要素生成を避ける
  - 文字列の埋め込みにマークアップ組み立てを使わない（入力文字列がそのまま画面に出るため）
  - 読み込み失敗の描画は、直前の図を残さない
  - 観測可能な完了状態: 各プランに対して描画が行われ、ブラウザ上で格子図・前提と限界・同一性・軌跡の 2 投影が表示される
  - _Requirements: 2.2, 2.6, 3.1, 3.3, 4.4, 5.3_
  - _Depends: 3.1, 3.2, 3.3_
  - _Boundary: Renderer_

- [ ] 4.2 画面を組み立て、ファイル選択と表示操作を結線する
  - 単一のページに、較正のバナー・キャッチ可能領域の図・前提と限界・同一性とパラメータ・軌跡の 2 投影を並べる。タブや画面遷移を作らない
  - ローカルファイルの選択で読み込み、差し替えを可能にする。**通信でファイルを取得しない**
  - 読み込みに失敗したら、直前の図を消してから失敗内容を表示する
  - 軸の選択・固定軸の値の選択・記録の選択・再生と停止・先頭復帰・任意時刻への移動を操作として提供する
  - 表示条件を変更しても**較正段階と除外要因の提示を再描画対象から外さない**
  - 保持する状態は現在のビュー・軸選択・選択中の記録・再生時刻と再生中か否かに限る。**永続化しない**
  - **パラメータを編集して結果を作り変える操作を作らない。複数結果の自動比較・差分表示も作らない**
  - 判断を画面側に置かない（位置・文言・分類はプラン層が決めている）
  - 観測可能な完了状態: ブラウザで掃引結果を選ぶと図・前提・同一性・アニメーションが表示され、軸切り替え・記録切り替え・再生操作が動き、別ファイルへ差し替えられる
  - _Requirements: 1.1, 1.3, 1.7, 2.7, 4.4, 4.5, 5.5, 5.8, 6.1, 6.2, 6.3, 6.4, 6.5, 8.4_
  - _Depends: 4.1_
  - _Boundary: App_

## 5. 境界の担保と最終確認

- [ ] 5. 境界の担保と最終確認

- [ ] 5.1 (P) ブラウザ側にアルゴリズムを持たないことの静的検査を実装する
  - 実装コードを構文木として走査し、モジュール間の依存が設計の依存方向の表に載る辺のみであることを検査する
  - 実装コードの取り込みが**相対参照のみ**であること、パッケージ定義の実行時依存が空であることを検査する
  - 通信・永続化に用いる識別子（取得要求・双方向通信・イベント購読・ビーコン送出・ブラウザ保存領域）が現れないことを検査する
  - 画面まわりの大域オブジェクトを参照してよいモジュールを、描画層・結線層・入口の 3 つに限ることを検査する
  - **数学関数の参照を許可リスト（最小・最大・絶対値・丸め・切り下げ・切り上げ）に限る。** 平方根・冪乗・三角関数・指数対数を禁止する
  - 宣言される名前が禁止語（予測・当てはめ・求解・積分・模擬・物理・重力・推定・外挿に相当する語）に前方一致しないことを検査する
  - **補間の宣言が唯一の実装 1 個に限られる**こと、重力に相当する数値リテラルが現れないことを検査する
  - 文字列リテラルに断定語（合否・合格・不合格・達成・NFR-7・PASS・FAIL）が現れないことを検査する
  - 許可リストと禁止語の一覧を**ソース内の定数として持つ**（広げる変更が差分として現れるようにする）
  - 検査ロジックは検査対象を取り込まず、常にソースをテキストとして読む
  - 観測可能な完了状態: 現状のコードに対して全 10 規則の検査が通り、テスト一括実行に組み込まれる
  - _Requirements: 1.5, 3.6, 3.7, 5.6, 5.7, 6.5, 7.1, 7.2, 7.3, 7.4, 7.6, 8.2_
  - _Depends: 4.2_
  - _Boundary: BoundaryCheck_

- [ ] 5.2 検査が違反を実際に検出することを証明する
  - 10 規則のそれぞれについて、**違反を含む架空のソース文字列**を検査関数へ渡し、違反が報告されることを確認する
  - 併せて、違反を含まない架空のソースが誤検出されないことも確認する
  - 検査ロジックを関数として切り出しておく必要があるため、5.1 で切り出した形をそのまま利用する
  - 観測可能な完了状態: 違反ソースに対して各規則が確実に失敗し、正常ソースに対して失敗しないことがテストで固定される
  - _Requirements: 7.5_
  - _Depends: 5.1_
  - _Boundary: BoundaryCheck_

- [ ] 5.3 ブラウザ上での確認と、上流の実出力との突き合わせを行う
  - ビルドして静的配信し、掃引結果の表示・格子点の詳細提示・軸切り替え後も前提提示が消えないこと・再生操作・現在時刻の表示を確認する
  - 必須項目を 1 つ削った入力で**図が出ず**欠落項目が列挙されること、図の表示後に壊れた入力を選ぶと前の図が消えることを確認する
  - 画面のどこにも断定語が現れないことを確認する
  - **上流 `trajectory-simulator` が実際に出力した掃引結果を 1 件読み込み**、設計の入力契約と食い違いが無いことを確認する
  - 食い違いがあった場合は**上流への確認事項として記録し、表示側で吸収しない**
  - 観測可能な完了状態: 上記の確認項目がすべて満たされ、上流の実出力 1 件が図として表示される（上流が未完成の段階では、この確認のみ上流完成まで保留とし、その旨を記録する）
  - _Requirements: 1.2, 1.3, 2.6, 3.6, 5.3, 5.5, 6.3, 8.3_
  - _Depends: 4.2_
